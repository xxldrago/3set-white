# Phase 3 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

**Extends Phase 2's approved contract.** Phase 2 (`02-UI-SPEC.md`) already locked the spacing
scale, the four type sizes / two weights, the 60/30/10 zinc + `#171717` accent + `#dc2626`
destructive palette, the status-color semantics, the inline destructive-confirm pattern, and the
core RU copy catalog. Phase 3 **introduces no new tokens, fonts, icons, or component library** —
it composes payment surfaces from the same primitives. Where this file repeats a Phase 2 value it
is to make the payment contract self-contained, not to re-open it.

## Payment Surfaces & Interaction Contract

### 1. Tariff → pay (extends `TariffPicker`)

- Below the live price, add one primary CTA using `pay.cta`. It is **disabled while `price === null`**
  (no order without a price) and while an order is being created.
- Tap → in-flight lock: disable, swap label to `pay.ctaLoading`, `POST /api/orders` (session-gated;
  body `{ kind: 'new', days, devices }`). Success returns `{ url }` → **same-tab redirect**
  (`window.location.assign(url)`) to the Platega hosted page. Failure → inline `role="alert"`
  `pay.createError` + `common.retry`, price stays rendered, CTA re-enabled.
- The provider's `url` and all secrets never live in component state beyond the redirect; no
  Platega identifier is ever rendered as a visible string.

### 2. Payment return / status (`/payments/[orderId]`, server component)

Order state machine (D-39): `pending → paid → provisioning → provisioned / failed`; Platega
terminal `CANCELED` / `CHARGEBACKED` are mapped to `canceled` / `refunded`.

| Display state | Chip | Body copy | Primary action |
|---------------|------|-----------|----------------|
| pending | zinc | `pay.pendingBody` | `pay.cta` (re-open stored Platega URL) |
| paid | amber | `pay.paidBody` | none (auto-advances) |
| provisioning | amber | `pay.provisioningBody` | none (auto-advances) |
| provisioned | green | `pay.provisionedBody` | `pay.toKey` + delivered sub-link/QR |
| failed | red | `pay.failedBody` | `common.retry` + `pay.toHistory` |
| canceled | zinc | `pay.canceledBody` | `pay.retry` |
| refunded | red | `pay.refundedBody` | `pay.toHistory` |
| unknown | zinc | `common.errorLoad` | `common.retry` |

- **"Получаем ключ…"** is a first-class state, not a spinner-only void: render the order summary
  (`{kind} · {price} ₽`), the `pay.provisioningBody` line, and a thin top progress bar
  (`absolute inset-x-0 top-0 h-0.5 animate-pulse bg-foreground`, the `TariffPicker` pattern).
- **Polling contract:** while status ∈ {pending, paid, provisioning}, a client island polls
  `GET /api/orders/{orderId}` every **3 s**. Polling stops on any terminal state. After **2 min**
  without a terminal state, stop polling and render `pay.pollingSlow` — never an endless spinner.
- **Provisioned** renders the delivered key using the **exact Phase 2 key-detail markup**: sub-link
  (`code.line-clamp-2 break-all`) + `CopyButton` + `QrSvg` + `key.qrCaption`, plus `pay.toKey`
  linking to `/keys/{keyId}`. If the key exists but the sub-link is not yet readable, degrade to
  Phase 2's `key.linkUnavailable` and hide copy + QR (never an empty QR) — the Phase 2 `partial`
  rule applies unchanged.
- **Never render raw Platega status strings, transaction ids, or ARTEMIDA error text** (D-19/D-24).
  Only the mapped RU labels above.

### 3. Renew (non-trial keys only)

- `renew.cta` («Продлить») renders on the subscription card and key-detail for **non-trial** keys.
- Opens `RenewPanel`: period selector (7/30/90, reuse `pricing.days*`) with live quote from
  `GET /api/pricing?days={days}&devices={currentDeviceLimit}` (D-43). Device count is fixed at the
  key's current limit for renew (D-45 adds days).
- Controls disabled until the first quote lands; a failed quote clears the last-good price
  (`pricing.error` + retry), matching `TariffPicker`. CTA label is `pay.cta`, same pipeline
  (`kind: 'renew'`, `keyId`).

### 4. Upgrade (non-trial keys only)

- `upgrade.cta` («Добавить устройство») renders on the card/detail for **non-trial** keys.
- `UpgradePanel`: integer stepper for devices to add, range `1 … (10 − currentDeviceLimit)`;
  live prorated quote from `GET /api/pricing` (D-43/D-45). `upgrade.body` explains the
  prorated charge. CTA `pay.cta`, pipeline `kind: 'upgrade'`, `keyId`.
- Stepper reuses the `TariffPicker` ± control styling (`h-11 w-11 rounded-full border …`,
  `tabular-nums`). Step bounds disable at min/max.

### 5. Trial keys (D-44 / Pitfall 6)

- On a trial key the renew and upgrade controls are **absent from the DOM** (not merely disabled)
  in both cabinet and bot. The only funding action is the existing `key.buyCta` («Купить подписку»)
  deep-linking to the tariff section. Backend mutation rejection (API 409) also maps to the same
  clean `trial.usedBody` family — never a raw 409.

### 6. Payment history (PAY-04 / D-46/47/48)

- **Cabinet:** dedicated route `app/payments/page.tsx` (session-gated, same shell wrapper), linked
  from the home page via `pay.toHistory`. Rows come from our `orders`/`payments` tables only —
  no live Platega request (D-46).
- **Row anatomy:** amount (`pay.amount`, `tabular-nums`) · `PaymentStatusChip` · date
  (`DD.MM.YYYY · HH:mm`) · what was bought (`{kind} · {keyName|keyId}`), where kind ∈
  new/renew/upgrade (D-48).
- **Bot:** a persistent menu button `bot.menuPayments` replies with the same rows as monospaced
  text, `kind · amount · date · status`, empty → `pay.historyEmpty`. Reply capped well under
  Telegram's 4096-char limit (Phase 2 slicing pattern).
- History reuses the Phase 2 error mapping (`common.errorLoad` / `common.errorUnavailable` /
  `common.errorRateLimit`) and the `SkeletonRows` loading fallback.

### 7. Bot channel (parity with the cabinet)

- After order creation the bot replies `bot.payCreated` + an inline **URL button** labeled
  `pay.cta` carrying the Platega URL (Telegram-safe; no visible raw URL required).
- On `provisioned`, the bot pushes `bot.payProvisioned` + the sub-link text + a generated QR
  photo (see rendering dependency above). On `failed`, it pushes `bot.payFailed` (no raw error).
- Every bot string resolves through `t()`; no provider text is ever echoed (D-16/D-19).

## Spacing Scale

Reuses the Phase 2 scale verbatim. **No new spacing values are introduced.**

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps, badge internal padding |
| sm | 8px | Compact element spacing, list-row internal gaps |
| md | 16px | Default element spacing, card internal gaps |
| lg | 24px | Card padding, section padding |
| xl | 32px | Gap between major page sections |
| 2xl | 48px | Page top/bottom padding (`py-12`) |
| 3xl | 64px | Reserved — not expected in the mobile payment layout |

Exceptions (inherited from Phase 2, still binding):
- **`12px`** permitted for tight intra-control gaps only: segmented-control items, status-chip
  padding, stepper button gaps.
- **Touch targets** are a minimum **44×44px**; primary CTAs are **48px** (`h-12`), secondary
  actions **44px** (`h-11`). Accessibility floor, not a spacing token.
- New payment surfaces use `h-11`/`h-12`; do not introduce `h-10` into payment controls.

Reuses the Phase 2 scale verbatim. **Exactly four sizes and exactly two weights across Phase 3.**

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Label | 14px | 400 | 1.4 |
| Body | 16px | 400 | 1.5 |
| Heading | 20px | 600 | 1.25 |
| Display | 30px | 600 | 1.2 |

Declared weights: **400 (regular)** and **600 (semibold)** — exactly two.

Rules:
- Map to Tailwind: `text-sm` (14), `text-base` (16), `text-xl` (20), `text-3xl` (30).
- Money and device counts use `tabular-nums` so live quotes/status changes never reflow.
- Body/status text uses the existing `text-zinc-600 dark:text-zinc-400` secondary-ink convention;
  headings use `text-black dark:text-zinc-50`.
- Status chips are 14px / 600. No new emphasis weight (never 500).

Accent reserved for (explicit — never "all interactive elements"):

3. Active item in the bottom nav / tab bar.
4. Focus ring on any interactive element (`outline-2`, `outline-offset-2`).

Accent is **not** used for: body links, status chips, card borders, unselected control labels, or
error/failure text.

**Order-status chips** (semantic extension of the Phase 2 status table — **chips and inline status

| Meaning | Light | Dark | Applied to |

`paid` uses amber (money received, key not yet delivered) so the user never reads "done" before the
key exists. Chip label is always text, never icon-only. No raw provider status string is rendered.
