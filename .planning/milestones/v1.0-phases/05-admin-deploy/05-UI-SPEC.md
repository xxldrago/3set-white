# Phase 5 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

**Extends Phase 4's approved contract, which extends Phase 3's, which extends Phase 2's.** Phases 2–4
already locked the spacing scale, the four type sizes / two weights, the 60/30/10 zinc + `#171717`
accent + `#dc2626` destructive palette, the semantic status-chip palette (green/amber/zinc/red), the
inline destructive-confirm pattern (`ConfirmPanel`), the skeleton/error copy catalog, and the RU i18n
discipline. Phase 5 **introduces no new tokens, fonts, icons, or component library** — it composes the
first **staff/admin surface** (`/admin/**`) from the same primitives and adds two new state-chip
mappings (balance health, broadcast status) plus one identity chip (role) that reuse existing hex.

**Scope boundary (ops ≠ UI).** OPS-01/OPS-02 — Docker Compose + Nginx + HTTPS on `64.188.97.106`,
Platega/Telegram webhooks on `my.3set.online`, and the White Label brand domain `sub.my.3set.online`
(D-72..D-78) — are **infrastructure ops with no user-facing surface** and are **out of this contract**.
The White Label domain is consumed server-side and already appears in the cabinet as the Phase 2
sub-link string; Phase 5 adds **no new cabinet UI**. Only the admin panel is contracted here.

**shadcn gate:** `components.json` absent; stack is Next.js 16 + React 19. The gate was resolved
**No** upstream (Phase 2 Design System; Phases 1/3/4 re-confirmed; the phase brief mandates hand-rolled
Tailwind with no component library). `npx shadcn info` is therefore not runnable — **Tool: none**. No
preset initialized this phase. Registry safety gate: not applicable.

**Admin-specific rendering & access dependencies (contract, not decoration):**
- **Access is Telegram-identity + role gated, server-side.** A signed-out visitor is redirected to
  `/login` (Phase 1 SessionError pattern). A signed-in caller who is not a staff member, or who lacks
  the required role for a section, receives **`notFound()` (404)** — never a distinct 403 page. This
  matches Phase 4's admin routes (D-51: a valid non-admin gets 404 so a forbidden route cannot be
  distinguished from a missing one) and prevents role enumeration. Section navigation is **filtered by
  role server-side** so a lower-privileged user never sees a link they cannot open.
- **The balance/stats read is cache-backed and degrades, never breaks.** ARTEMIDA balance/keys/devices
  (ADM-04) are read server-side; on 502/503/429 the section renders its mapped error or an `unknown`
  balance chip while our-DB stats still render. No provider error text, HTTP code, or `Retry-After`
  value is ever rendered (D-19/D-24).
- **Broadcast is outbox-queued, not synchronous** (D-71). The composer reflects a queued/sending/sent
  state from our queue and does **not** poll a per-recipient progress feed; there is **no fake
  percentage progress bar**.
- **The admin panel is desktop-first but fully token-conformant.** It reuses the exact spacing,
  typography, and color tokens; the only layout latitude is a wider content column and card-per-row
  stacking of tables on small screens (see Spacing / UI Considerations).

## Admin Surfaces & Interaction Contract

### 1. Access, roles & navigation

Role matrix (D-64/D-65 — standard matrix; server-side, not advisory):

| Section | administrator | support | manager |
|---------|:---:|:---:|:---:|
| Обзор / статистика (`/admin`) | ✓ | — | ✓ |
| Пользователи (`/admin/users`) | ✓ | ✓ | ✓ |
| Профиль — ключи | ✓ | ✓ | — |
| Профиль — платежи | ✓ | — | ✓ |
| Профиль — обращения | ✓ | ✓ | — |
| Обращения (`/admin/tickets`) | ✓ | ✓ | — |
| Рассылка (`/admin/broadcast`) | ✓ | — | — |
| Роли (`/admin/roles`) | ✓ | — | — |

- The `app/admin/**` layout (`AdminShell`) runs the role gate **server-side before any section renders**.
  Signed-out → `redirect('/login')`. Signed-in with no staff role, or wrong role for the section →
  **`notFound()` (404)**. There is **no distinct "forbidden" page or copy** — a lower-privileged user
  must not be able to distinguish a forbidden section from a missing one (D-51).
- `AdminNav` renders **only** the links the caller's role permits; an unpermitted section is **absent
  from the DOM** (not disabled, not greyed, no lock icon). The panel never advertises what the user
  cannot open.
- **Nav anatomy:** a top horizontal bar (admin is desktop-first) — `flex flex-wrap gap-2`; each item is
  a pill link `h-11 rounded-full px-4`. The active item uses the accent treatment
  (`bg-foreground text-background`); inactive items use the secondary-button recipe. The bar wraps to a
  second line on narrow screens and **never horizontally overflows** the viewport.
- **Header:** `admin.title` («Админ-панель») as the page `h1` (30/600), plus `admin.currentRole`
  («Ваша роль: {role}») rendered with `RoleChip`, so a staff member always knows their scope. A
  secondary `admin.toCabinet` («Кабинет») link returns to `/`.
- **Role chips are identity, not status** — all three roles use the **neutral zinc** tint with the
  literal RU label. Do **not** color-code roles (no invented hierarchy semantics).

### 2. Stats dashboard (`/admin`) — administrator + manager

- Landing section, server-rendered `StatsPanel`, `dynamic = 'force-dynamic'`.
- **Metric cards** (card surface, `p-6`, `grid grid-cols-1 gap-4 sm:grid-cols-2 lg:grid-cols-3`):
  - From our DB (ADM-03): `admin.statsRevenue` (period revenue, `{amount} ₽`, `tabular-nums`),
    `admin.statsUsers` (count), `admin.statsOrders` (payments count).
  - From ARTEMIDA (ADM-04): `admin.statsKeys` (keys count), `admin.statsDevices` (devices count),
    `admin.statsBalance` (`{amount} ₽`) trailed by a `BalanceChip`.
- **Period selector** for revenue: reuse the Phase 2 segmented-control pattern
  (`pricing.days7/days30/days90` labels); the selected segment uses the accent. Default **30 days**.
  Changing the period re-queries via a client island (`router.refresh` with a search param) and shows
  skeleton cards while it resolves.
- **Balance health** (`BalanceChip`, threshold from env — D-70):
  - `ok` → green (`admin.balanceOk`)
  - `low` (below threshold, still usable) → amber (`admin.balanceLow`)
  - `critical` (depleted / issuance at risk) → red (`admin.balanceCritical`)
  - `unknown` (ARTEMIDA read failed) → zinc (`admin.balanceUnknown`)
- **`BalanceAlert` banner** — rendered at the top of `/admin` **only** when balance is `low` or
  `critical`: amber wash for `low`, red wash for `critical`, with the matching body copy. No top-up
  control is offered (top-up is a manual ARTEMIDA action, D-73) — the banner only informs. Because it
  is a **persistent standing condition** it uses `role="status"` (polite); the assertive `role="alert"`
  is reserved for transient action errors.
- **Degradation:** if the ARTEMIDA read fails, the three ARTEMIDA cards render `—` and the balance chip
  reads `unknown` while the DB-backed cards still render. A DB read failure renders `common.errorLoad`
  + `common.retry` **for that card group only**. The dashboard never blanks entirely.
- Loading → skeleton cards (`h-24 animate-pulse rounded-2xl`). Money uses `tabular-nums`; render the
  stored/provider amount verbatim (`Intl.NumberFormat('ru-RU')` + ` ₽`) — never recompute or re-round.

### 3. User search (`/admin/users`)

- Session + role gated (administrator / support / manager). Heading `admin.searchLabel`
  («Поиск пользователя»).
- **Form:** one `<input>` (`h-12`) labelled `admin.searchLabel`, placeholder `admin.searchPlaceholder`
  («Telegram ID или ключ»); submit is a primary button `admin.searchCta` («Найти пользователя»). Accepts an exact
  numeric telegram-id **or** a key/customer reference (`q`; the server may also match `customerRef`).
  Value is trimmed; submit is disabled while blank or in flight (`admin.searchCtaLoading` «Ищем…»).
- **States:**
  - **idle** (nothing submitted): `admin.searchIdle` («Введите Telegram ID или ключ, чтобы найти
    пользователя.») in a card — never an empty-list illusion.
  - **loading:** 3 `SkeletonRows`.
  - **results** (`UserSearchResults`): count header (`tp('admin.searchCount')`, only when ≥ 2) + rows.
    Row anatomy: display name (or `—`), `admin.profileTelegramId`, and an optional `RoleChip` when the
    user is staff; the whole row links to `/admin/users/[id]`. Exact matches first.
  - **no results:** `admin.searchNoResults` («Пользователи не найдены. Проверьте ID или ключ.») in a
    card; the query text stays in the field.
  - **error:** `admin.searchError` + `common.retry`; query text stays.
- **Overflow / long lists:** results scroll in page flow. If matches exceed **50**, render the first 50
  plus `admin.searchMore` («Показаны первые 50 результатов. Уточните запрос.»). Never a fixed-height
  inner scroll region.
- **Long text:** a long display name / key reference truncates 1 line with `title` (full value); the
  telegram-id uses `tabular-nums`.

### 4. User profile (`/admin/users/[id]`) — administrator / support / manager (sub-sections by role)

- Unknown id → `notFound()`. Header `admin.profileTitle` («Профиль пользователя») with
  `admin.profileTelegramId` and `admin.profileCreated` (`DD.MM.YYYY`), plus a `RoleChip` when the user
  is staff.
- **Role action (administrator only):** an `admin.rolesChange` («Изменить роль») control opens the
  role-change confirm (see §6). Absent from the DOM for support/manager.
- **Three independent sub-sections**, each its own card, each loading/degrading independently (a
  failure in one never blanks the others). Visible per the matrix above:
  1. **Keys** (`admin.profileKeys`): read-only `AdminKeyRow` list — name, key-status chip, expiry
     (`DD.MM.YYYY`), device count (`key.devicesCount`). **No renew/upgrade controls** — admins view,
     never mutate user keys (those are user-initiated). Empty → `admin.profileNoKeys`.
  2. **Payments** (`admin.profilePayments`): `PaymentHistoryList` read-only (amount, `PaymentStatusChip`,
     date, kind). Empty → `admin.profileNoPayments`.
  3. **Tickets** (`admin.profileTickets`): ticket rows (`TicketStatusChip` + last activity) linking to
     `/admin/tickets/[id]`. Empty → `admin.profileNoTickets`.
- **Partial:** if the ARTEMIDA keys read fails, the Keys sub-section alone renders `admin.profilePartial`
  + `common.retry`; header/payments/tickets still render. The same applies per our-DB section. An
  **empty** sub-section and an **errored** sub-section are visually distinct (different copy) — never a
  shared blank.
- Loading → per-section `SkeletonRows`.

### 5. Broadcast (`/admin/broadcast`) — administrator only

- Heading `admin.broadcastTitle` («Рассылка»). Card containing:
  - `<textarea>` labelled `admin.broadcastLabel` («Текст сообщения»), placeholder
    `admin.broadcastPlaceholder` («Введите текст рассылки…»), `min-h-28`, `maxLength=4000`, `resize-y`;
    body 16/400/1.5.
  - Recipient count line `admin.broadcastRecipients` («Получателей: {n}»), `tabular-nums`, `text-sm`
    secondary ink.
  - Primary CTA `admin.broadcastCta` («Отправить рассылку»), **disabled while the trimmed text is
    blank** or while a request/queue is in flight.
- **Confirm (irreversible mass send):** the first tap opens the inline `AdminConfirmPanel` in the
  **`primary` variant — not the red destructive style** (a send is not a deletion). Panel copy
  `admin.broadcastConfirmTitle` / `admin.broadcastConfirmBody` («…Отменить отправку будет нельзя.») /
  confirm `admin.broadcastConfirmCta` («Отправить»). Escape or `common.cancel` dismisses with **no
  request**; the mutation fires only on the explicit second tap. Never `window.confirm`.
- **States** (D-71 outbox/queue):
  - in-flight → CTA locks, label `admin.broadcastSending` («Отправляем…»).
  - queued → `BroadcastStatusChip` `queued` (zinc) + `admin.broadcastQueued`.
  - sending → chip `sending` (amber).
  - sent → chip `sent` (green) + `admin.broadcastSent`; the composer clears.
  - failed → chip `failed` (red) + `admin.broadcastFailed` + `common.retry`; **the typed text is
    retained**.
- **No progress bar** — the worker batches per D-71; the UI shows queue state only. Status copy renders
  in a `role="status"` region. The full message text is never echoed into the status panel.

### 6. Roles management (`/admin/roles`) — administrator only

- Heading `admin.rolesTitle` («Роли») + `admin.rolesSubtitle` («Управление доступом сотрудников —
  только для администратора.»).
- **List of `admin_users`** (D-64): columns telegram-id, display name, `RoleChip`, action
  `admin.rolesChange`. At `sm+` → a real `<table>` inside an `overflow-x-auto` container; below `sm` →
  the same rows become **stacked cards** (label/value pairs). No column is ever clipped without a scroll
  affordance.
- Empty → `admin.rolesEmpty` («Сотрудники ещё не добавлены.»). Loading → `SkeletonRows`. Error →
  `common.errorLoad` + `common.retry`.
- **Role change** opens the inline `AdminConfirmPanel`:
  - Raising/assigning a role → **`primary` variant**; copy `admin.roleChangeTitle` /
    `admin.roleChangeBody` («Новая роль: {role}. Права доступа изменятся сразу.») /
    `admin.roleChangeConfirm`.
  - **Downgrading an administrator** (any change that removes administrator access) → **`destructive`
    variant (red)**; copy `admin.roleDowngradeTitle` / `admin.roleDowngradeBody` («{name} потеряет
    доступ к управлению ролями и рассылке.») / `admin.roleDowngradeConfirm`.
  - Escape / `common.cancel` → no request; the mutation fires only on the explicit second tap.
  - **Self-change blocked:** the current administrator's own row shows the control **disabled** with
    `admin.rolesSelf` («Это ваша учётная запись — роль изменить нельзя.») — prevents last-admin
    lockout. This is a UI guard; the backend must enforce the same.
  - Failure → `admin.roleChangeError` + `common.retry`; the row stays on its old role.
- The roles table and any stat breakdown obey the same mobile card-stacking rule.

### 7. Admin ticket queue (`/admin/tickets`, `/admin/tickets/[id]`) — administrator + support

- Reuses Phase 4's `TicketList` / `TicketThread` / `TicketComposer` / `TicketStatusChip` and the
  existing `/api/admin/tickets/**` routes verbatim (D-51). The admin list shows **all** tickets (not
  owner-scoped) with the same row anatomy (subject, status chip, last activity, preview, unread). An
  optional single-select status filter (open/answered/closed) reuses the Phase 4 chip vocabulary — no
  new status strings.
- Empty → `ticket.emptyHeading` (reuse). Loading → `SkeletonRows`. Error → `common.errorLoad` +
  `common.retry`. Overflow → page flow. Count → `tp('ticket.count')`.
- Reply/close are the existing admin actions; the reply composer is Phase 4's, unchanged. No raw
  ticket id or provider text is rendered.

## Spacing Scale

Reuses the Phase 2/3/4 scale verbatim. **No new spacing values are introduced.**

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps, chip internal padding |
| sm | 8px | Compact element spacing, table cell gaps, list-row gaps |
| md | 16px | Default element spacing, card internal gaps |
| lg | 24px | Card padding, section padding |
| xl | 32px | Gap between major page sections |
| 2xl | 48px | Page top/bottom padding (`py-12`) |
| 3xl | 64px | Reserved — page-level spacing on wide viewports |

Exceptions (inherited, one new layout — not a token):
- **`12px`** permitted for tight intra-control gaps only: chip padding, segmented items, stepper gaps.
- **Touch targets** minimum **44×44px**; primary CTAs **48px** (`h-12`), secondary actions **44px**
  (`h-11`). Accessibility floor, not a spacing token. Do not introduce `h-10` into admin controls.
- **Admin content width:** the admin shell widens its content column to **`max-w-6xl` (72rem)** at
  `sm+` to fit tabular/dashboard data; mobile retains the `px-6` gutter. This is a **container-width
  choice, not a new spacing token**.
- **Admin tables:** card-per-row stacked layout below `sm`; a real `<table>` inside `overflow-x-auto`
  at `sm+`. Cell padding uses existing tokens (`px-4 py-3` / `p-3`). A table never clips a column
  without a horizontal scroll affordance.

## Typography

Reuses the Phase 2/3/4 scale verbatim. **Exactly four sizes and exactly two weights across Phase 5.**

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Label | 14px | 400 | 1.4 |
| Body | 16px | 400 | 1.5 |
| Heading | 20px | 600 | 1.25 |
| Display | 30px | 600 | 1.2 |

Declared weights: **400 (regular)** and **600 (semibold)** — exactly two.

**Focal point (visual anchor per screen):**
- `/admin` (dashboard): the ARTEMIDA **balance card + `BalanceAlert` banner** is the anchor.
- `/admin/users` (search): the **search input** is the anchor.
- `/admin/users/[id]` (profile): the **profile header (telegram-id + `RoleChip`)** is the anchor.

- `/admin/broadcast`: the **composer textarea + send CTA** is the anchor.

Rules:
- Map to Tailwind: `text-sm` (14), `text-base` (16), `text-xl` (20), `text-3xl` (30).
- Metric numbers (revenue, balance, counts) are **30/600 `tabular-nums`** so values never reflow;
  card titles are 20/600; labels/meta/timestamps are 14/400.
- Role/status/balance/broadcast chips are **14/600**. No new emphasis weight (never 500).
- Body/secondary text stays on `text-zinc-600 dark:text-zinc-400`; headings on
  `text-black dark:text-zinc-50`.

**Formatting rules:**
- Money: `Intl.NumberFormat('ru-RU')` + ` ₽`; thousands separator is a non-breaking space; currency is
  always RUB. Render the stored/provider amount verbatim — never recompute or re-round.
- Dates: `DD.MM.YYYY · HH:mm` for activity/timestamps, `DD.MM.YYYY` for registration and key expiry
  (matching Phase 2/3).
- Counts and money use `tabular-nums`; `{role}`, `{name}`, `{n}`, `{id}`, `{amount}`, `{date}` are always
  interpolated through `t()`/`tp()`, never string-concatenated.
