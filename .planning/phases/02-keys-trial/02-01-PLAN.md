  <name>Write the ARTEMIDA V1 live probe (dry-run first)</name>
  <read_first>.planning/phases/02-keys-trial/02-RESEARCH.md sections "ARTEMIDA Paid API V1 — Observed Contract", "Request/response shapes", "Assumptions Log"; scripts/check-manifest.mjs</read_first>
  <files>scripts/artemida-probe.mjs</files>
  <action>
Create a dependency-free Node ESM script (`node:fs`/`node:process` only). It reads
`ARTEMIDA_API_KEY` and `ARTEMIDA_BASE_URL` (default `https://artemida.cc/v1`) from
`process.env`, sends `Authorization: Bearer`, and probes:
GET `/pricing?days=7&devices=2`, `?days=30&devices=2`, `?days=90&devices=2`,
`?days=7&devices=1` (the A7 minimum-devices question), GET `/keys`, GET `/balance`.
To lock the CAB-04/CAB-03 shapes too: after `GET /keys`, if the body contains at least
one key, chain `GET /keys/{firstId}`, `GET /keys/{firstId}/subscription-links` and
`GET /keys/{firstId}/devices`; if the account has no keys, record those three as
`UNKNOWN (no key available)` rather than omitting them.
Print, per call, the HTTP status, the full raw JSON body, and the `X-Request-Id` /
`Retry-After` headers. Never print the key or the `Authorization` header.

A `--dry-run` flag prints the planned method+URL+body list (marking the key-scoped
calls conditional on a key existing) and exits 0 without any network call (this is
how the plan is verified before the key exists). A
`--confirm-trial` flag additionally issues exactly one `POST /trial` with a
`customerRef` argument and a fresh `crypto.randomUUID()` `Idempotency-Key`, because a
trial consumes the account's one-time offer — it must be explicitly opted into, never
run by a bare invocation. A `--json` flag emits a machine-readable summary
`{ pricing, keys, keyDetail?, subscriptionLinks?, devices?, balance, trial? }` of the
parsed bodies to stdout (the contract-lock task redirects it into a committed
`docs/artemida-v1-contract.json`).

On any non-2xx response, print the status and the error envelope and continue to the
next call (the probe is diagnostic, not fail-fast). Do not import from `lib/` — this
is a standalone dev script and must run before `lib/env.ts` gains the ARTEMIDA vars.
  </action>

    <automated>node --check scripts/artemida-probe.mjs && node scripts/artemida-probe.mjs --dry-run</automated>
    <fails_when>non-zero exit, or the dry-run output does not list at least the six unconditional planned GET request lines (pricing x4, /keys, /balance) plus the conditional key-scoped lines</fails_when>
  </verify>
