<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser to BFF | the session cookie is the only identity source |
| BFF/bot to Postgres | keys_cache rows are scoped by user |
| background revalidation to ARTEMIDA | provider data crosses here after the response is sent |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-02-13 | Information disclosure / Tampering | IDOR on key reads | high | mitigate | Every read scoped by session telegram-id → owning `userId`; no lookup by bare `keyId`; `after()` revalidation is also user-scoped |
| T-02-14 | Repudiation / correctness | stale cache status | medium | mitigate | `statusKind` derived from `expiresAt` vs `now`, not the stored status; `status.unknown` fallback (Pitfall 6) |
| T-02-15 | Denial of service | unbounded background revalidation | low | accept | Single user-scoped call per cabinet open; no queue in v1; revisit if volume demands |
| T-02-16 | Information disclosure | provider error in `after` | low | mitigate | Errors in the background callback are caught + `logger.warn`; they never surface to the response |
| T-02-SC | Tampering | npm installs | high | mitigate | No new packages in this plan |
</threat_model>
