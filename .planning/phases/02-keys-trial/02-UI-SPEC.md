## Design System

| Property | Value |
|----------|-------|
| Tool | none |
| Preset | not applicable |
| Component library | none (hand-rolled Tailwind components — established by `LoginButton.tsx`, `InstallPrompt.tsx`) |
| Icon library | none — inline SVG only, 20px/24px grid, `stroke-width="1.5"`, `currentColor` (zero-dependency, consistent with Phase 1 shell) |
| Font | Geist Sans via `next/font` (`--font-geist-sans`) |

**shadcn gate:** `components.json` absent; stack is Next.js 16 + React 19 — gate would normally prompt. Upstream decision already locked **No** (CONTEXT.md: "no component library yet beyond Tailwind + hand-rolled components"; Phase 1 built a zero-dependency mobile-first shell). No shadcn preset is initialized this phase. Registry safety gate: not applicable.

**Font rationale:** `app/globals.css` currently sets `font-family: Arial, Helvetica, sans-serif` on `body`, silently overriding the loaded Geist face. This phase **must** remove that override and apply Geist via the existing `--font-sans` token (Tailwind `font-sans`) so cabinet, login, and guides render identically. No new font is added.

**Phase 2 rendering dependency (contract, not decoration):** QR codes are rendered **server-side** from the BFF `subscription-links` payload — never client-side, never via a third-party image URL. Recommended: `qrcode` npm package (`toSvg()`), output `<svg viewBox="0 0 256 256">`, error correction `M`, quiet zone `4`. The QR encodes only the ARTEMIDA `subscriptionUrl`. The executor may choose a different server-side renderer, but the contract "QR is a locally-rendered SVG of `subscriptionUrl`" is binding.

## Spacing Scale

Declared values (must be multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps, badge internal padding |
| sm | 8px | Compact element spacing, list-row internal gaps |
| md | 16px | Default element spacing, card internal gaps |
| lg | 24px | Card padding, section padding |
| xl | 32px | Gap between major page sections |
| 2xl | 48px | Page top/bottom padding (`py-12`) |
| 3xl | 64px | Reserved — not expected in Phase 2 mobile layout |

Exceptions:
- **`12px`** permitted for tight intra-control gaps only: segmented-control items, badge/status-chip padding, stepper button gaps.
- **Touch targets** are a minimum **44×44px**; primary CTAs are **48px** tall (`h-12`) and secondary actions **44px** (`h-11`). This is an accessibility floor, not a spacing token.
- **`gap-3` (12px), `h-10` (40px)** appear in the Phase 1 shell. New Phase 2 surfaces use the declared tokens and `h-11`/`h-12`; do not propagate `h-10` to new controls.
- Grid gaps may combine tokens (e.g. `gap-y-2` + `gap-x-4`) but each axis value comes from the scale.

## Typography

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Label | 14px | 400 | 1.4 |
| Body | 16px | 400 | 1.5 |
| Heading | 20px | 600 | 1.25 |
| Display | 30px | 600 | 1.2 |

Declared weights: **400 (regular)** and **600 (semibold)** — exactly two.

Rules:
- Only these four sizes are used for new Phase 2 UI. Map to Tailwind: `text-sm` (14), `text-base` (16), `text-xl` (20), `text-3xl` (30).
- **Phase 1 shell normalization:** `text-lg` (18px) sub-headings and `font-medium` (500) section titles in `app/page.tsx`, `app/login/page.tsx`, `app/guides/page.tsx` are legacy. Any element Phase 2 touches uses the declared set — sub-headings become 16px body or 20px heading; emphasis becomes 600, never 500.
- Numeric/price figures use `tabular-nums` so live price updates do not reflow.
- Body text color stays on the existing `text-zinc-600 dark:text-zinc-400` secondary-ink convention; headings use `text-black dark:text-zinc-50`.

| Secondary (30%) | `#ffffff` · dark `#18181b` (zinc-900) | Cards, list rows, tariff panel, nav bar |

| Destructive | `#dc2626` (red-600) · dark `#f87171` (red-400) | Destructive actions only |

Border/divider token (existing pattern): `rgba(0,0,0,0.10)` light · `rgba(255,255,255,0.15)` dark.

Accent reserved for (explicit — never "all interactive elements"):
1. Primary CTA fills — "Попробовать", "Купить подписку", "Перейти к оплате", "Скопировать" (confirmed state).
2. Selected state of the tariff segmented controls — chosen days chip and device-count selection.
3. Active item in the bottom nav / tab bar.
4. Focus ring on any interactive element (`outline-2`, `outline-offset-2`).

Accent is **not** used for: body links (use secondary ink + underline), status badges, card borders, unselected control labels, or destructive actions.

Status colors (semantic extension — **badges and inline status text only**, never buttons or backgrounds):

| Meaning | Light | Dark | Applied to |
|---------|-------|------|------------|
| Active | `#16a34a` (green-600) | `#4ade80` (green-400) | `status.active` badge |
| Expiring / Trial | `#d97706` (amber-600) | `#fbbf24` (amber-400) | `status.expiring`, `trial.badge` |
| Expired / Pending / Unknown | `#71717a` (zinc-500) | `#a1a1aa` (zinc-400) | `status.expired`, `status.pending`, `status.unknown` |
| Destructive | `#dc2626` | `#f87171` | delete/clear confirm button fill + error text |

The trial badge (`TRIAL`) MUST be visually distinct from paid keys (PITFALLS § "Trial and paid keys visually identical"): amber chip + explicit Latin label, rendered on every trial key card and on the trial key detail screen. Badges are text chips (14px, 600 weight, `rounded-full`, tinted background at ~12% opacity), never icon-only.

All copy is RU, stored in `lib/i18n/messages/ru.ts`, referenced only by key. No user-visible surface ever renders a raw ARTEMIDA error, status code, or English string (D-19 / D-24).

|---------|----------|------|

| Tariff continuation CTA | `pricing.cta` | Перейти к оплате |
| Empty state heading (subscriptions) | `subs.emptyHeading` | У вас пока нет подписок |

| Retry affordance (all error states) | `common.retry` | Повторить |
| Destructive confirmation — delete one device | `devices.deleteTitle` / `devices.deleteBody` / `devices.deleteConfirm` | Удалить устройство? / Устройство «{name}» будет отключено от ключа. Его можно будет подключить заново по ссылке. / Удалить устройство |

| Cancel (destructive + all dialogs) | `common.cancel` | Отмена |

**Destructive confirmation approach (D-32):** inline confirmation panel rendered **inside** the affected card/row — not `window.confirm`, not a native `<dialog>`, not a browser alert. It replaces the row's action area with the title + body + two buttons (`common.cancel` secondary, red-filled confirm). Requires an explicit second tap; Escape or Cancel dismisses with no request. Focus stays trapped within the panel while open. No type-to-confirm — device removal is recoverable by re-linking, and clear-all never deletes the key itself.

**Formatting rules:**
- Prices render exactly as ARTEMIDA returns (D-28) — no markup, no rounding beyond display formatting. Format with `Intl.NumberFormat('ru-RU')` and append ` ₽`; thousands separator is a non-breaking space.
- Traffic: when the key is unlimited (v1 default, `trafficLimitGb = 0`), show "`{used} использовано`"; when a limit exists, show "`{used} из {limit}`". Humanize to GB with one decimal ≥ 1 GB, MB below.
- Dates: `DD.MM.YYYY` (`ru-RU`), full date, no relative wording inside `status.expiring` beyond `{days} дн.`.
- `{seconds}` from the ARTEMIDA `Retry-After` header, never a hardcoded value.

## UI Considerations

> Shape-rooted UI *state* coverage (empty / loading / error / populated / partial / overflow / zero-one-many / long-text). Empty- and error-state COPY live in `## Copywriting Contract` above; this section covers state coverage and REFERENCES those rows rather than restating copy.

Applicable state considerations resolved: **13 covered, 2 backstop, 0 unresolved**.

| Category | Element(s) | Status | Resolution / Reason |
|----------|------------|--------|---------------------|
| empty | subscriptions-list | ✅ covered | Zero keys renders `subs.emptyHeading` + `subs.emptyBody` + `trial.cta`; verified by an empty-state render test. |
| empty | devices-list | ✅ covered | Zero devices renders `devices.empty`; the "Сбросить все" control is hidden when the list is empty. |
| loading | subscriptions-list | ✅ covered | On cache miss (D-29) render 3 skeleton rows (`h-16`, `animate-pulse`, `rounded-2xl`); on cache hit render cached rows immediately and revalidate with no layout shift. |
| loading | tariff-picker | ✅ covered | Until the first `GET /api/pricing` resolves, controls render disabled at the last known price with a thin top progress bar; days/device taps are no-ops. Subsequent device changes update price in place (D-27) without disabling. |
| loading | trial-cta | ✅ covered | In-flight trial disables the CTA and swaps label to `trial.ctaLoading`; a per-key/per-user in-flight lock prevents double submit (PITFALLS § per-key locks). |
| error | subscriptions-list | ✅ covered | Load failure renders `common.errorLoad` (or `common.errorUnavailable` for 502/503) + `common.retry`; raw API text is never shown (D-19/D-24). |
| error | tariff-picker | ✅ covered | Pricing failure renders `pricing.error` + `common.retry`; controls stay disabled, last-good price is cleared rather than shown stale. |
| error | key-detail | ✅ covered | Subscription-link fetch failure renders `key.linkError` + `common.retry`; QR area shows a neutral placeholder, copy button hidden. |
| partial | key-detail | ✅ covered | Missing traffic/limit renders "—"; missing `subscriptionUrl` hides the copy + QR block and shows `key.linkUnavailable` (never an empty QR). |
| partial | subscriptions-list | ✅ covered | Rows with unknown/absent status render the neutral `status.unknown` badge; missing expiry renders "—"; the card still renders. |
| zero-one-many | subscriptions-list | ✅ covered | 0 → empty state; 1 → single card, no count header; ≥2 → count header via RU plural key (`subs.countOne/Few/Many`). |
| overflow | subscriptions-list | ✅ covered | The list scrolls in page flow (no fixed-height inner scroll region); the page grows vertically on mobile. |
| populated | subscriptions-list | ✅ covered | One card per key showing name, status badge, expiry, and device usage; ordered active → expiring → expired → pending. |
| long-text | key-detail (subscription URL) | 🧪 backstop | Long sub-link wraps with `break-all`, clamps to 2 lines with ellipsis, and keeps the copy button always visible/≥44px; held-out visual test at a 200-character URL. |
| long-text | device names | 🧪 backstop | Device label truncates with ellipsis at container width, full value exposed via `title`; held-out visual test with a 60-character device name. |
