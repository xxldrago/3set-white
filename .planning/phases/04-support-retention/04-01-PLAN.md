Define and export:
- `type TicketStatus = "open" | "answered" | "closed"` and `type TicketAuthor = "user" | "support"`.
- `interface AttachmentDescriptor { path: string; mime: string; sizeBytes: number; width: number | null; height: number | null }` — a plain structural type (do NOT import `lib/attachments.ts`; that module lands in plan 04-02 in parallel).
- `interface CreateTicketInput { telegramId: bigint; subject: string; body: string; attachment?: AttachmentDescriptor | null }`.
- `interface TicketListRow { id: string; subject: string; status: TicketStatus; unreadForUser: number; lastMessageAt: Date; preview: string | null }`.
- `interface TicketThread { id: string; subject: string; status: TicketStatus; unreadForUser: number; messages: Array<{ id: string; author: TicketAuthor; body: string | null; createdAt: Date; attachments: Array<{ id: string; mime: string; width: number | null; height: number | null; sizeBytes: number }> }> }`.

`createTicket(input)`: resolve the owning `User` by `telegramId` (return a typed `{ kind: "no_user" }` if absent — never create a user here); in ONE `prisma.$transaction`, create the `Ticket` (status `open`, `unreadForUser: 0`) and the first `TicketMessage` (`author: "user"`, body), and — when `attachment` is present — the child `Attachment` row inside the same transaction. Return `{ kind: "created"; id: string }`.

`listTicketsForUser(telegramId)`: `prisma.ticket.findMany({ where: { user: { telegramId } }, orderBy: { lastMessageAt: "desc" } })`, mapping `preview` to the newest message's body (or null for image-only) — newest-activity-first per UI-SPEC §1.

`getTicketForUser(telegramId, ticketId)`: ownership join `prisma.ticket.findFirst({ where: { id: ticketId, user: { telegramId } }, include: { messages: { orderBy: { createdAt: "asc" }, include: { attachments: true } } } })`; a non-owned ticket is indistinguishable from missing → `null` (T-ticket-idor, no oracle).

Also export two bot-intake helpers (used by plan 04-07): `beginSupportPrompt(telegramId)` → `updateMany` set `awaitingSupport: true, supportPromptAt: now`; `isSupportPromptFresh(supportPromptAt: Date | null, now?: Date): boolean` → true only when set and `< 30 * 60_000` ms old; `clearSupportPrompt(telegramId)` → set `awaitingSupport: false`.

Write `tests/unit/tickets-service.test.ts` (DB-backed, real local Postgres; use the `tests/unit/keys-service.test.ts` cleanup/`beforeAll`/`afterAll` pattern, owner + other telegram ids): create → row is `open` in the single queue; `listTicketsForUser` returns it newest-first; `getTicketForUser` returns the thread for the owner and `null` for a non-owner; `createTicket` for an unknown telegram id returns `{ kind: "no_user" }` and creates nothing; `isSupportPromptFresh` boundary (29 min true, 31 min false, null false).
