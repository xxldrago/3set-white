  <action>
Install `sharp@^0.35.5` (`npm install sharp@^0.35.5`). Then create `lib/attachments.ts` as a SERVER-ONLY module (mirror the `lib/qr.ts` header discipline: no Next imports; `import sharp from "sharp"`).

Export:
- `export const MAX_ATTACHMENT_BYTES = 5 * 1024 * 1024;` (5 MiB, D-54).
- `export class UnsupportedImageError extends Error {}`.
- `export interface NormalizedAttachment { data: Buffer; mime: string; width: number; height: number; sizeBytes: number }`.
- `export async function normalizeImage(input: Buffer): Promise<NormalizedAttachment>` — reject `input.byteLength === 0 || > MAX_ATTACHMENT_BYTES` with `UnsupportedImageError`; build `sharp(input, { failOn: "error", limitInputPixels: 4096 * 4096, animated: false })`; read `metadata()`; reject when `meta.format` is not in `{jpeg, png, webp}` (magic-byte truth, never the filename/MIME); then `.rotate().resize({ width: 1600, height: 1600, fit: "inside", withoutEnlargement: true }).webp({ quality: 80 }).toBuffer({ resolveWithObject: true })`; return `{ data, mime: "image/webp", width: info.width, height: info.height, sizeBytes: data.byteLength }`. Wrap decode failures in `UnsupportedImageError`.
- `export async function saveAttachment(ticketId: string, n: NormalizedAttachment): Promise<string>` — name = `${randomUUID()}.webp`, abs = `path.join(UPLOAD_DIR, ticketId, name)`, `mkdir(dirname(abs), { recursive: true })`, `writeFile(abs, n.data, { flag: "wx" })`, return `path.relative(UPLOAD_DIR, abs)` (RELATIVE only, never absolute).
- `export async function readAttachment(relPath: string): Promise<Buffer>` — `abs = path.resolve(UPLOAD_DIR, relPath)`; throw `new Error("attachments:path_escape")` when `!abs.startsWith(UPLOAD_DIR + path.sep)`; else `readFile(abs)`.
- `const UPLOAD_DIR = path.resolve(env.UPLOAD_DIR);` — add the env field in THIS task first so this module typechecks: extend `lib/env.ts` `envSchema` with `UPLOAD_DIR: z.string().min(1).default("/data/uploads")` and `ADMIN_TELEGRAM_IDS: z.string().optional()` (comma-separated telegram ids; empty/unset = no admins), following the existing `CRON_SECRET` optional pattern and the server-only comment convention; never expose via `NEXT_PUBLIC_*`. Keep the import at module top.

`ticketId` is used only as a directory segment; never interpolate a caller-supplied filename (Pitfall 2). Log nothing about bytes/paths.

Write `tests/unit/ticket-attachments.test.ts` (unit, real sharp on darwin, no DB/network): generate real jpeg/png/webp fixtures with `sharp` in-memory; assert `normalizeImage` accepts all three and returns `mime === "image/webp"`; assert a plain-text/garbage Buffer throws `UnsupportedImageError`; assert a 3000px image is downscaled to ≤1600; assert an empty Buffer and a >5 MiB Buffer throw; assert `readAttachment` throws for `"../escape"` and for an absolute path; assert `saveAttachment` writes under `UPLOAD_DIR` and returns a relative path (use a temp UPLOAD_DIR via env for the test, or assert the returned path does not start with the absolute dir).

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| client / Telegram → normalizeImage | Untrusted bytes cross here (multipart File, or a Bot API download). |
| attachments module → local filesystem | A server-generated path is written; a DB path is read back. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-04-05 | Tampering | normalizeImage format check | high | mitigate | Format decided from `sharp.metadata().format` allow-list `{jpeg,png,webp}`; client filename/MIME ignored; SVG/HTML rejected (Task 2 tests). |
| T-04-06 | Tampering / Elevation | saveAttachment / readAttachment paths | high | mitigate | `randomUUID()` storage name; relative path stored; `path.resolve(...).startsWith(UPLOAD_DIR + sep)` guard (Task 2 tests). |
| T-04-07 | Denial of Service | image decode | high | mitigate | 5 MiB byte cap before decode; `limitInputPixels: 4096*4096`; `animated: false`; `failOn: "error"` (Task 2). |
| T-04-08 | Information Disclosure | attachment logs | high | mitigate | No bytes/paths/message bodies logged (module logs nothing); enforced again at serve/dispatch. |
| T-04-09 | Information Disclosure | public attachment URL | high | mitigate | No public URL is ever produced; only the gated same-origin route (plan 04-04) serves bytes (D-56). |
