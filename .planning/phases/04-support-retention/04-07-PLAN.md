  <action>
Add the bot support channel to `lib/bot.ts`, reusing the existing keyed-branch discipline (try/catch → keyed reply; log `{ updateId, telegramId, outcome }` only).

1. Add a menu row entry to the `/start` keyboard: a button labelled `t("bot.menuSupport")`.
2. `bot.hears(t("bot.menuSupport"), ...)`: call `beginSupportPrompt(BigInt(from.id))` (04-01) then `ctx.reply(t("bot.supportPrompt"))`.
3. `bot.on(["text", "photo"], ...)` BEFORE/alongside the other text handlers such that it returns early when not armed: load the user row; compute `isSupportPromptFresh(user.supportPromptAt)`; if `!user?.awaitingSupport || !fresh` → `return` (fall through — do not consume). Otherwise, BEFORE any download/create, atomically CLAIM the flag via the single-winner `clearSupportPrompt(BigInt(from.id))` defined in 04-01; if the claim returns `false` (a concurrent/retried update already claimed it) → `return` without creating anything (claim-before-create). Then:
   - If `ctx.message.photo` exists, take the LARGEST (`photos[photos.length - 1]`), `const link = await ctx.telegram.getFileLink(largest.file_id)`, `const res = await fetch(link)`, `const bytes = Buffer.from(await res.arrayBuffer())`, `const normalized = await normalizeImage(bytes)`, `const path = await saveAttachment(<ticketScope>, normalized)` — note the ticket id is created by the service, so save under a per-user/uuid scope and pass the descriptor into `createTicket` (mirror the cabinet route composition from 04-04). Wrap the download/normalize in a try/catch → `bot.ticketError` on failure.
   - `const subject = (ctx.message.text ?? ctx.message.caption ?? "").slice(0, 120)` (fall back to a keyed default subject when a photo has no caption); `createTicket({ telegramId: BigInt(from.id), subject, body: (ctx.message.text ?? ctx.message.caption ?? "").slice(0, 4000), attachment })`.
   - On `{ kind: "created" }` → `ctx.reply(t("bot.ticketCreated"))` (the flag is already claimed — do NOT clear it again); on `no_user`/failure → `ctx.reply(t("bot.ticketError"))`. Reply only keyed copy.
4. Add to `lib/i18n/messages/ru.ts`: `bot.menuSupport` ("Поддержка"), `bot.supportPrompt`, `bot.ticketCreated`, `bot.ticketError` (UI-SPEC copy). Do not add keys no code references.

The photo size guard: reject a downloaded buffer that exceeds the attachment cap by letting `normalizeImage` throw `UnsupportedImageError` and mapping it to `bot.ticketError` (never a raw error). Do not log the buffer or the file link.
