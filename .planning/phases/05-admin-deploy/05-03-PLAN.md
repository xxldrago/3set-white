| Boundary | Description |
|----------|-------------|
| admin → `POST /api/admin/broadcast` | Untrusted body; administrator-only; enqueues, never sends inline |
| worker → Telegram Bot API | Delivery to N recipients; per-recipient error classification decides terminal vs retry |
| composer island → broadcast route | Client-supplied text is zod-validated; the status panel never reflects raw provider output |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-05-09 | Tampering | broadcast body / Bot API parse | high | mitigate | Plain-text `sendMessage` (NO parse_mode); zod trim min 1 max 4000; administrator-only |
| T-05-10 | Denial of Service | broadcast retry storm on dead chats | high | mitigate | 403/400 terminal `failed` (never reschedule); 429/5xx backoff; per-recipient UNIQUE dedupe key (Pitfall 5) |
| T-05-11 | Information Disclosure | broadcast wrong-chat send | high | mitigate | Resolve the owning `User.chatId ?? telegramId` server-side; never a caller-supplied chat (mirrors T-04-10) |

| T-05-14 | Elevation of Privilege | broadcast route/page | high | mitigate | `requireRole("administrator")` on the route AND the page; 404 on any other role |
