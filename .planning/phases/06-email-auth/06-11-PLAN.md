<objective>
Close WR-01 and WR-03: password change/reset re-mints only the current request's session while every other 30-day JWT stays valid (compromise recovery is broken), and a new reset request leaves earlier unused reset tokens live for their full 1h TTL. Add a per-user `credentialsChangedAt` watermark compared against each token's `iat` in the session gates, and delete prior unused reset tokens when issuing a new one.

Purpose: make password rotation and reset actually revoke prior access, as a money-handling service requires.
Output: schema migration, session-gate revocation, watermark bumps on change/reset/unlink, reset-token supersession, and integration tests.
</objective>
