# Phase 7 — UI Design Contract

> Visual and interaction contract for the Phase 7 admin analytics surface. Generated by
> gsd-ui-researcher, verified by gsd-ui-checker.

**Extends the shipped v1.0 contracts (`05-UI-SPEC.md` et al.), with one correction:** the palette was
re-branded after Phase 5 to the 3set light-only tokens in `app/globals.css` (`--color-lime`,
`--color-line`, `--color-muted`, `--color-green`, …). **Phase 7 uses those tokens and nothing else.**
The zinc / `#171717` / `#dc2626` palette in the archived specs is superseded — do not reintroduce it.

**Scope in one paragraph.** Phase 7 ships a new read-only admin page at `/admin/analytics` plus a
one-card MRR teaser on `/admin`. The first screen is exactly three blocks (D-10): the KPI row → the
MRR waterfall → the MRR sparkline. The page is **desktop-first**, **server-rendered**, **light-only**,
uses **pure SVG** (no chart library, zero new packages) and **no client state** other than the existing
`PeriodSelector`. There are no destructive actions and no primary CTA — the only interactions are the
period switch and the «Подробнее» link.

**Explicit non-goals (do not add):** custom `from`/`to` date range (the existing `PeriodSelector`
supports only the three presets — verified in code), chart tooltips / JS hover, CSV export,
tariff/kind breakdowns, margin or runway figures (Phase 8), dark-mode variants, icons, gradients,
shadows.

### 5.2 Page shell, role gate, and the period control

`app/admin/analytics/page.tsx` — RSC, `export const dynamic = 'force-dynamic'`.

- **Role gate first, inside the page** (RSC payloads skip layouts — D-11 / Pitfall 12). Copy the exact
  shape from `app/admin/page.tsx:22-29`: `try { ({ role } = await requireRole('administrator','manager')) }`
  → `SessionError` → `redirect('/login')`, `AdminError` → `notFound()`, anything else rethrow.
- **`?period=` normalization:** `Number(params.period ?? 30)`; accept only `7 | 30 | 90`, everything
  else → `30`. Identical to `app/admin/page.tsx:31-33`. No `from`/`to` parsing.
- **Shell:**

  ```tsx
  <section className="flex flex-col gap-6">
    <header className="flex flex-wrap items-center justify-between gap-3">
      <h2 className="text-xl font-semibold text-foreground">{t('admin.analyticsTitle')}</h2>
      <div className="w-full sm:w-80"><PeriodSelector selected={period} /></div>
    </header>
    <Suspense fallback={<KpiSkeleton />}><AnalyticsKpi period={period} /></Suspense>
    <Suspense fallback={<ChartSkeleton className="h-72" />}><MrrWaterfall /></Suspense>
    <Suspense fallback={<ChartSkeleton className="h-24" />}><MrrSparkline period={period} /></Suspense>
  </section>
  ```

  The period control sits **top-right of the page header** (full width below `sm`) — the page-level
  scope control, matching its position on `/admin`. No subtitle, banner, breadcrumb, or extra block on
  the first screen (D-10).
- **What the period changes — state this in code comments, never guess:**
  - KPI: ARPU, ARPPU and cost coverage are windowed by `period`; **MRR/ARR are point-in-time (now)** and
    deliberately do not move.
  - Sparkline: window = `period` days.
  - Waterfall: **fixed** to the trailing 6 MSK months (§5.4) and always labelled as such. This is the
    only scope divergence on the page and it is labelled — no block's window is ever implicit.
- **`PeriodSelector` changes (two one-liners, they benefit every admin page):**
  1. the container gets `role="group"` alongside the existing `aria-label={t('admin.statsPeriod')}`
     (a bare `aria-label` on a `div` is ignored by assistive tech);
  2. every button gets `focus-visible:outline-2 focus-visible:outline-offset-2 focus-visible:outline-green`.
  Buttons stay `h-11` (44px) with `aria-pressed`; labels stay `admin.statsPeriod7/30/90`.
- **Degradation:** each of the three blocks is its own async server component with its own
  `try/catch`; a failing block renders its heading (when it has one) plus `common.errorLoad`, and the
  other blocks still render. No retry button — the page is `force-dynamic`, a reload retries.

### 5.3 Block 1 — KPI row (MRR is the headline)

Reuse `GRID` (`grid grid-cols-1 gap-4 sm:grid-cols-2 lg:grid-cols-3`) and `CARD`
(`flex flex-col gap-2 rounded-2xl border border-line p-6 border-line`). DOM order = D-10 order:
**MRR, ARR, ARPU, ARPPU, coverage** → visually row 1 = MRR (spans 2) + ARR; row 2 = ARPU, ARPPU, coverage.

| Card | Label key | Value | Size | Sub-line |
|------|-----------|-------|------|----------|
| MRR | `admin.analyticsMrr` | `{mrr} ₽` | **hero 30/600** | `tp('admin.analyticsActiveKeys', n)` |
| ARR | `admin.analyticsArr` | `{mrr × 12} ₽` | compact 20/600 | `t('admin.analyticsArrSub')` — «MRR × 12» |
| ARPU | `admin.analyticsArpu` | `{arpu} ₽` or «—» | compact 20/600 | `t('admin.analyticsArpuSub', { n })` — «все пользователи: {n}» |
| ARPPU | `admin.analyticsArppu` | `{arppu} ₽` or «—» | compact 20/600 | `t('admin.analyticsArppuSub', { n })` — «платящие: {n}» |
| Cost coverage | `admin.analyticsCoverage` | `{pct}%` or «—» | compact 20/600 | `t('admin.analyticsCoverageSub', { known, total })` |

- **Hierarchy rule (non-negotiable):** MRR is the only 30px number on the page and the only card laid
  out as a horizontal band — label + sub on the left, value right-aligned on the baseline
  (`sm:col-span-2 sm:flex-row sm:items-end sm:justify-between`). ARR sits directly beside it and states
  its derivation («MRR × 12»), so the pair reads as one idea: *run-rate*. ARPU/ARPPU are per-user
  derivatives (supporting); coverage is a data-quality gauge (supporting).
- **Hero markup** (the `size="hero"` branch of `MetricCard`):

  ```tsx
  <div className={`${CARD} sm:col-span-2 sm:flex-row sm:items-end sm:justify-between`}>
    <div className="flex min-w-0 flex-col gap-1">
      <span className="text-sm text-muted">{label}</span>
      {sub && <span className="text-xs text-muted">{sub}</span>}
    </div>
    <span className="text-3xl font-semibold tabular-nums text-foreground">{value}</span>
  </div>
  ```

  `default` keeps today's vertical anatomy at `text-2xl` (used by `/admin` only). `compact` uses the
  same vertical anatomy at `text-xl`. The extraction must be behaviour-preserving: `RevenuePanel`'s
  rendered output is unchanged.
- **Value rules:**
  - Money KPIs are **whole rubles**, `Intl.NumberFormat('ru-RU')` + ` ₽`, `Math.round` where a ratio is
    involved; never decimals, never a second currency.
  - **Denominator 0 → «—», never «0 ₽»** (ARPU with 0 users, ARPPU with 0 payers).
  - MRR/ARR with 0 active keys render **`0 ₽`** — a genuinely-zero point-in-time value, with the sub
    saying «0 активных подписок». Never «—» for a value that is truly zero.
  - Every number carries `tabular-nums`.
- **Cost-coverage states (the coverage variant):**

  | Data | Value | Sub |
  |------|-------|-----|
  | `total > 0 && known > 0` | `{round(known / total * 100)}%` | `себестоимость известна для {known} из {total} заказов` |
  | `total > 0 && known === 0` | **«—»** | `себестоимость известна для 0 из {total} заказов` |
  | `total === 0` | **«—»** | `за период не было оплаченных заказов` (`admin.analyticsCoverageNoOrders`) |

  Coverage is the **only cost-derived figure on this page**; no margin number is rendered in Phase 7.
  When Phase 8 adds margin, the rule is already fixed: **unknown margin renders «—», never `0`**.
  «—» (not `0%`) is used when `known === 0` because "no cost data" must not look like "cost data
  exists and sums to zero".
- **Loading:** `KpiSkeleton` = the same `GRID` with five `aria-hidden` divs
  `h-32 animate-pulse rounded-2xl bg-foreground/5` (the first one `sm:col-span-2`).
- **Error:** one `CARD` containing `text-sm text-muted` + `t('common.errorLoad')`.

### 5.4 Block 2 — MRR waterfall

**Model, stated once so it cannot drift:** a single SVG, one group per MSK month, drawn as a
**signed grouped bar chart around a shared zero line** — four component bars (new ↑, expansion ↑,
contraction ↓, churned ↓) plus a **net-change marker** (horizontal tick + dot) in the same group.
Within a group the reconciliation identity `new + expansion − contraction − churned = net` is read
left-to-right. There are **no floating connectors between months** (that would require six separate
waterfalls inside one SVG), and therefore no cumulative total line.

- **Window:** the trailing **6 Europe/Moscow calendar months ending with the current month**. MRR is a
  point-in-time metric, so the current month is complete, not partial. If history is shorter, render
  `min(6, months since the first paid order)` slots, minimum 1 — never fabricate empty months before
  the business existed. A month with no activity **inside** the window keeps its slot (zero-height
  bars), so the axis never skips a month.
- **Header:**

  ```tsx
  <div className="flex flex-wrap items-baseline justify-between gap-2">
    <h3 className="text-xl font-semibold text-foreground">{t('admin.analyticsWaterfallTitle')}</h3>
    <span className="text-xs text-muted">{t('admin.analyticsWaterfallWindow')}</span>
  </div>
  ```

- **Panel + scroll affordance (a11y):**

  ```tsx
  <div role="region" tabIndex={0} aria-label={t('admin.analyticsWaterfallTitle')}
       className="overflow-x-auto rounded-2xl border border-line bg-panel p-4
                  focus-visible:outline-2 focus-visible:outline-offset-2 focus-visible:outline-green">
    <svg viewBox="0 0 640 260" className="h-64 w-full min-w-[40rem]" aria-hidden="true" focusable="false">…</svg>
  </div>
  ```

  `bg-panel` on the plot area is required — lime needs a defined light surface (see §Color). Below `lg`
  the chart **scrolls, never shrinks**; the region is keyboard-scrollable.
- **Geometry (exact):** `W=640, H=260, PAD_L=64, PAD_R=8, PAD_T=16, PAD_B=32`; plot height `= 212`;
  `zeroY = PAD_T + 106 = 122`; `slot = (W − PAD_L − PAD_R) / months.length`; each group has five
  sub-slots (`slot / 5`); `barW = 12`, bars centred in their sub-slot; `maxAbs = max(|value|)` across
  all components **and** nets; `barH = (|v| / maxAbs) × (106 − 6)`. Positive bars grow up from
  `zeroY`, negative bars grow down. A component with `v > 0` renders at least **2px**
  (FunnelCharts convention); `v === 0` renders nothing — no 2px stub, zero must look like zero.
- **Marks and token usage (no hex literals anywhere; Tailwind v4 maps `--color-*` to `fill-*` /
  `stroke-*`. If a utility is missing, use `fill="var(--lime)"` — never a hex literal):**

  | Mark | Class / attributes | Notes |
  |------|--------------------|-------|
  | Zero line | `stroke-line-2`, `strokeWidth={1}`, spans the full plot width | The only horizontal rule |
  | Y ticks (`+maxAbs`, `0`, `−maxAbs`) | `fill-muted`, `fontSize={9}`, `textAnchor="end"`, `x={PAD_L − 8}` | `Intl.NumberFormat('ru-RU')`, no «₽» (the block is in rubles) |
  | Month labels | `fill-muted`, `fontSize={9}`, `textAnchor="middle"`, `y={H − 8}` | `MM.YY` (e.g. «07.26»), same convention as `FunnelCharts.shortLabel(…, 'month')` — numeric formatting, not copy |
  | New | `fill-lime stroke-green`, `strokeWidth={1}` | Brand accent; the green hairline is what makes lime legible on white |
  | Expansion | `fill-green` | Same "growing" family, darker |
  | Contraction | `fill-line-2` | Negative by **direction** (below zero), never red |
  | Churned | `fill-muted` | Darker neutral, below zero |
  | Net change | `stroke-foreground` `strokeWidth={2}` tick across ~70% of the group width + `fill-foreground` dot `r={3}` at group centre, `y = y(net)` | A marker, not a bar — it must not read as a fifth component |

  **No red or amber anywhere.** The palette has no semantic destructive token and churn is not an
  action; sign is carried by direction relative to the zero line.
- **No tooltip.** Zero JS: each mark carries a native `<title>` —
  `{legendLabel} · {MM.YYYY} — {money.format(value)} ₽` (e.g. «Новые · 07.2026 — 12 500 ₽»).
- **Legend** (HTML under the panel, `flex flex-wrap items-center gap-4 text-xs text-muted`; each item
  `flex items-center gap-1`): swatch `h-2 w-2 rounded-sm` — `bg-lime border border-green`, `bg-green`,
  `bg-line-2`, `bg-muted`; for net a `h-0.5 w-3 rounded-full bg-foreground`. Labels come from the five
  `admin.analyticsWf*` keys.
- **Accessible data table:** immediately after the legend, `sr-only`:
  `<table><caption>{t('admin.analyticsWfTable')}</caption>` with columns
  `admin.analyticsTableMonth` + the five `admin.analyticsWf*` labels, one row per month, values
  `money.format(v)` (rubles are stated in the caption). The SVG is `aria-hidden`, so the table is the
  single source of truth for assistive tech — a 30-number chart cannot be described by one
  `aria-label` (deliberate difference from `FunnelCharts`' `role="img"`).
- **States:**
  - **Empty** (no paid subscription ever): heading + window label stay; panel body is
    `text-sm text-muted` + `t('admin.analyticsWfEmpty')`; no axes, no legend, no table.
  - **Sparse month:** slot and label render, all bars zero-height, net dot on the zero line.
  - **Loading:** `h-72 animate-pulse rounded-2xl bg-foreground/5` (`aria-hidden`).
  - **Error:** heading stays, body = `text-sm text-muted` + `common.errorLoad`.

### 5.5 Block 3 — MRR sparkline

- **Window:** the selected `period` (7/30/90) days, MSK. Header:

  ```tsx
  <div className="flex flex-wrap items-baseline justify-between gap-2">
    <h3 className="text-xl font-semibold text-foreground">{t('admin.analyticsSparkTitle')}</h3>
    <span className="text-xs text-muted">{t('admin.analyticsSparkMeta', { n: period, value: money.format(last) })}</span>
  </div>
  ```

  → «30 дн. · МСК · сейчас 412 500 ₽». The trailing-window label is mandatory and always names МСК.
- **Panel:** `rounded-2xl border border-line bg-panel p-4`, then
  `<svg viewBox="0 0 320 64" preserveAspectRatio="none" className="h-16 w-full" aria-hidden="true" focusable="false">`.
  Fluid width, **no horizontal scroll** — the sparkline is a trend glyph, not a readable axis.
- **Marks:**
  - Area: a closed `<path>` down to `y = H − 4`, `fill-lime`, `fillOpacity={0.35}`.
  - Line: a single `<polyline>` `fill="none"`, `stroke-green`, `strokeWidth={2}`,
    `vectorEffect="non-scaling-stroke"` (keeps the stroke crisp under `preserveAspectRatio="none"`),
    `strokeLinejoin="round"`, `strokeLinecap="round"`.
  - **No last-point marker** — with non-uniform scaling a dot would render as an ellipse. The latest
    value is stated as text in the header instead (`analyticsSparkMeta`).
- **Point construction:** one point per `daily_metrics` day in the window plus today's live value;
  x is proportional to the **day index within the window** (gaps show as a longer segment, never a
  collapsed equal spacing); no synthetic zero points are invented for days with no row.
  `y` uses min–max scaling with `span = Math.max(1, max − min)`; when `max === min` and `max > 0`
  the line sits on the vertical centre; when `max === 0` it sits on the bottom edge (a true zero).
- **Degradation:** fewer than **2** points → `text-sm text-muted` + `t('admin.analyticsSparkEmpty')`
  inside the same panel (a single dot is not a trend). Brand-new installs land here.
- **Accessible data table:** `sr-only` `<table>` after the panel,
  `<caption>{t('admin.analyticsSparkTable')}</caption>`, columns `admin.analyticsTableDate` /
  `admin.analyticsTableMrr`, one row per plotted point, `DD.MM.YYYY`, `money.format(v)`.
- **Loading:** `h-24 animate-pulse rounded-2xl bg-foreground/5` (`aria-hidden`).
- **Error:** heading stays, body = `text-sm text-muted` + `common.errorLoad`.

### 5.6 Data contract the UI renders (pin the shapes, not the SQL)

```ts
loadKpis(period)      → { mrr, arr, activeKeys, arpu, arppu,
                          arpuDenominator, arppuDenominator,
                          coverageKnown, coverageTotal }
loadWaterfall()       → { months: { label /* "YYYY-MM" */, new, expansion,
                                    contraction, churned, net }[] }
loadSparkline(period) → { points: { day /* "YYYY-MM-DD" */, mrr }[] }
```

- All three loaders are called from their own server component; none may import another's result.
- «—» is a **render decision**, never a sentinel number: the loaders return `null` for an undefined
  ratio (0 denominator) and the component renders «—».
- The current day is always the live value, not the last nightly row (D-12).

### 5.7 Responsive behaviour

| Breakpoint | KPI | Waterfall | Sparkline |
|------------|-----|-----------|-----------|
| `< 640` (base) | 1 column, stacked; MRR hero is vertical | scrolls (`min-w-[40rem]`) inside the bordered panel | fluid, `h-16` |
| `640–1023` (`sm`) | 2 columns; MRR spans both | scrolls, same panel | fluid |
| `≥ 1024` (`lg`) | 3 columns; row 1 = MRR(2)+ARR, row 2 = ARPU+ARPPU+coverage | full width, no scroll | fluid |

The admin shell already supplies `max-w-6xl`, `px-6 py-12 sm:px-16`, `gap-8`. Page-level vertical
rhythm is `gap-6`; card grids use `gap-4`. The nav wraps rather than overflows at any width.

### 5.8 Accessibility

- **Charts:** both SVGs are `aria-hidden="true" focusable="false"`; each is paired with an `sr-only`
  `<table>` that carries the same numbers (captions state «МСК» and «в рублях»). This is the contract,
  not a nicety — color-only encoding of ±MRR is otherwise unreadable to AT.
- **Waterfall scroll region:** `role="region"` + `tabIndex={0}` + `aria-label` (the block heading) so
  keyboard users can scroll it; visible focus ring `outline-green`.
- **Focus:** every interactive element on this page uses
  `focus-visible:outline-2 focus-visible:outline-offset-2 focus-visible:outline-green` — the period
  segments, the nav item, the «Подробнее» link, the scroll region. Never `outline-none` without a
  replacement.
- **Contrast (checked against the real tokens):**
  - `--muted` (#5b645e) on `--panel` (≈6.6:1) and on `--background` (≈5.8:1) — safe for 14px/12px text.
  - `--dim` (#8f968f) is ≈3:1 — **never used for text on this page** (placeholders/disabled only).
  - `--lime` (#b7ff45) is ≈1.2:1 on white — **never text**; only as a fill, always with a
    `stroke-green` hairline, or as `text-lime` on `bg-foreground` (≈14:1, the nav/period active pill).
  - `--green` (#0c4f36) on white ≈10:1 — safe for the sparkline stroke.
- **Motion:** no animation beyond the existing `animate-pulse` skeletons; no chart transitions;
  `prefers-reduced-motion` needs no special handling here.
