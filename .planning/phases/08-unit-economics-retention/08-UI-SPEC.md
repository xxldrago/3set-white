# Phase 8 — UI Design Contract

> Visual and interaction contract for the Phase 8 unit-economics and retention surface.
> Generated by gsd-ui-researcher, verified by gsd-ui-checker.

**Extends `07-UI-SPEC.md` verbatim.** Phase 7 already fixed the design system (light-only 3set
tokens, hand-rolled Tailwind v4, pure SVG, Russian copy, no shadcn). Phase 8 **adds two sections below
the sparkline** and changes nothing above them. Where this document is silent, Phase 7 §5.2–§5.9 is
the contract; where this document is explicit, it wins for the new blocks only.

**Scope in one paragraph.** `/admin/analytics` gains, in order and below the existing first screen
(KPI → waterfall → sparkline, untouched): a section «Юнит-экономика» with three LTV cards, three
margin/cost cards and two burn/runway cards; and a section «Удержание» with three period cards and a
compact 6-MSK-month churn table. Five new server components, five `Suspense` boundaries, five
independent `try/catch`es. Read-only: **no forms, no modals, no new navigation, no destructive
actions, no client components, no new npm dependencies.**

**Explicit non-goals (do not add):** a second page or route, drill-down into a user, cohort matrix
(Phase 10), funnel/timings (Phase 9), CSV export, alerting on low runway (future ALR-03), balance
history chart, goodwill «выдано бонусом» line (see deviations), any red/amber semantic color, any
chart in these two sections (cards + one table only).

## Surface & Interaction Contract

### 6.1 Page composition — where the two sections go

Append to the existing `<section className="flex flex-col gap-6">` in
`app/admin/analytics/page.tsx`, **after** `<MrrSparkline period={period} />`. Nothing above moves.

```tsx
<Suspense fallback={<ChartSkeleton className="h-24" />}>
  <MrrSparkline period={period} />
</Suspense>

<AnalyticsSection title={t('admin.analyticsUnitTitle')}>
  <Suspense fallback={<CardsSkeleton count={3} />}>
    <LtvCards />
  </Suspense>
  <Suspense fallback={<CardsSkeleton count={3} />}>
    <MarginCards period={period} />
  </Suspense>
  <Suspense fallback={<CardsSkeleton count={2} twoUp />}>
    <BurnRunwayCards />
  </Suspense>
</AnalyticsSection>

<AnalyticsSection title={t('admin.analyticsRetentionTitle')}>
  <Suspense fallback={<CardsSkeleton count={3} />}>
    <RetentionCards period={period} />
  </Suspense>
  <Suspense fallback={<ChartSkeleton className="h-64" />}>
    <ChurnTable />
  </Suspense>
</AnalyticsSection>
```

- **`AnalyticsSection` anatomy** (the only new structural element on the page):

  ```tsx
  <section aria-label={title} className="flex flex-col gap-4 border-t border-line pt-6">
    <h2 className="text-xl font-semibold text-foreground">{title}</h2>
    {children}
  </section>
  ```

  The `border-t border-line pt-6` is the chapter break — **no new color, no new radius, no new size**.
  `aria-label` on the `<section>` makes it a named landmark without a second visible heading.
- **Two levels of heading, deliberately:**

  | Level | Element | Size / weight | Where |
  |-------|---------|---------------|-------|
  | Section | `h2` | 20px / 600 (Unbounded via global CSS) | «Юнит-экономика», «Удержание» |
  | Block | `h3` | **16px / 600** (Unbounded) | `analyticsLtvTitle`, `analyticsMarginTitle`, `analyticsBurnTitle`, `analyticsRetentionCardsTitle`, `analyticsChurnTitle` |

  The 16px block heading is what distinguishes a nested block from the 20px page/first-screen headings.
  Do **not** put `font-display` on any number, and do not reuse `text-xl` for the nested `h3`.
- **Block header recipe** (identical in all five blocks; window label always present):

  ```tsx
  <div className="flex flex-wrap items-baseline justify-between gap-2">
    <h3 className="text-base font-semibold text-foreground">{title}</h3>
    <span className="text-xs text-muted">{windowMeta}</span>
  </div>
  ```

- **`CardsSkeleton`** lives in `page.tsx` next to `KpiSkeleton`/`ChartSkeleton`:
  `<div className={twoUp ? 'grid grid-cols-1 gap-4 sm:grid-cols-2' : GRID} aria-hidden="true">` with
  `count` × `<div className="h-32 animate-pulse rounded-2xl bg-foreground/5" />`.
- **Degradation:** each of the five blocks resolves independently; a failure renders that block's
  heading + window meta (when the window is known without data) + `text-sm text-muted` +
  `t('common.errorLoad')`. No retry button — the page is `force-dynamic`, a reload retries. A failure
  in `BurnRunwayCards` (including `GET /balance`) never affects the other four blocks (D-15).
- **`?period=`** keeps its current normalization (7 | 30 | 90 → else 30) and its header position. New
  consumers: `MarginCards` and `RetentionCards`. `LtvCards`, `BurnRunwayCards` and `ChurnTable`
  **ignore `period`** by decision (D-04, D-14, D-20) — their labels say so.

### 6.2 «LTV» block — three cards, three different windows

`LtvCards` (no props). Layout `GRID` (1 / 2 / 3 columns). All cards `size="compact"` (20px value).

| Order | Label key | Value | Sub key / sub text |
|-------|-----------|-------|--------------------|
| 1 | `admin.analyticsLtvGrossHist` — «LTV gross, исторический» | `{₽}` or «—» | `analyticsLtvGrossHistSub` → «за всё время · платящих: {n}» |
| 2 | `admin.analyticsLtvGrossPred` — «LTV gross, прогноз» | `{₽}` or «—» | `analyticsLtvGrossPredSub` → «30 дней · месячный отток {value}» |
| 3 | `admin.analyticsLtvNet` — «LTV net» | `{₽}` or «—» | `analyticsLtvNetSub` → «с {date} · платящих: {n}» |

- **Header meta:** `t('admin.analyticsLtvMeta')` → «не зависит от периода». This is the only block whose
  window is *per card* — the block-level meta must say so, because D-20 forbids an implicit window.
- **Card 2 sub `{value}`** is the monthly logo churn rate used as the divisor, formatted per §Copywriting
  (`«2,4%»`, `«12%»`), or «—» when the divisor is 0. Never «∞».
- **Card 3 `{date}`** is the MSK day (`DD.MM.YYYY`) of the earliest paid order with
  `providerCost ≠ null`; «21.10.2026» is the fallback literal when history is empty. When no costed
  order exists: value «—», sub `t('admin.analyticsLtvNetNoCost')`.
- **Gross vs net comparison rule (D-03):** the cards sit side by side but their subs state **different
  windows**. Do not add a delta, a ratio, or a "net is X% of gross" line — that would compare
  non-comparable bases.
- **Empty (no payer ever):** all three values «—»; subs read «за всё время · платящих: 0»,
  «30 дней · месячный отток —», «нет заказов с известной себестоимостью». No block-level empty banner
  (the sub-lines are the explanation, same pattern as the Phase 7 KPI row).
- **Error:** heading + meta survive; body `text-sm text-muted` + `common.errorLoad` inside one `CARD`.

### 6.3 «Маржа и себестоимость» block — three windowed cards

`MarginCards({ period })`. Layout `GRID`. All cards `size="compact"`.

- **Header meta** (window + coverage in one line — this *is* the coverage badge; no chip component):

  | Data | Meta |
  |------|------|
  | `totalOrders > 0` | `t('admin.analyticsWindowCoverage', { n: period, known: costedOrders, total: totalOrders })` → «30 дн. · МСК · покрытие 4 из 9 заказов» |
  | `totalOrders === 0` | `t('admin.analyticsWindowCoverageNoOrders', { n: period })` → «30 дн. · МСК · за период не было оплаченных заказов» |

| Order | Label key | Value | Sub |
|-------|-----------|-------|-----|
| 1 | `admin.analyticsGrossMargin` — «Валовая маржа» | `{₽}` or «—» | `admin.analyticsGrossMarginSub` — «деньги минус себестоимость» |
| 2 | `admin.analyticsMarginPct` — «Маржинальность» | `{pct}` or «—» | `admin.analyticsMarginPctSub` — «маржа ÷ выручка по заказам с себестоимостью» |
| 3 | `admin.analyticsCostPerKey` — «Средний расход на ключ» | `{₽}` or «—» | `admin.analyticsCostPerKeySub` — «на оплаченный заказ» |

- **Negative margin** (cost > cash) is a legal value: render the Intl minus sign, `text-foreground`,
  **no red**. Sign is carried by the character, exactly as Phase 7 does for negative waterfall values.
- **Partial coverage (D-11):** never extrapolate. The cards show the costed subset only; the meta line
  is the only place the denominator is stated. `known === 0` → all three values «—», meta still states
  «покрытие 0 из M заказов» (never `0%` for margin %).
- **Empty:** meta switches to the no-orders key; cards «—». No extra banner.
- **Error:** heading survives (meta dropped — it is data-derived), body `text-sm text-muted` +
  `common.errorLoad`.

### 6.4 «Расход и запас баланса» block — two cards

`BurnRunwayCards()` (no props; fixed 30 MSK days + live balance). Layout is a **2-up grid**, not `GRID`:
`grid grid-cols-1 gap-4 sm:grid-cols-2`. Both cards `size="compact"`.

- **Header meta:** `t('admin.analyticsWindowCoverage', { n: 30, known, total })` or, when `total === 0`,
  `t('admin.analyticsWindowCoverageNoOrders', { n: 30 })`. Always names «30 дн.» — this block does not
  follow `?period` (D-14).

| Order | Label key | Value | Sub |
|-------|-----------|-------|-----|
| 1 | `admin.analyticsBurnRate` — «Средний расход в день» | `{₽}/день` or «—» | `admin.analyticsBurnRateSub` — «себестоимость заказов ÷ 30 дней» |
| 2 | `admin.analyticsRunway` — «Запас дней» | `{n} дн.` or «—» | see the three states below |

- **Runway sub states (D-15) — the sub is where the derivation becomes auditable:**

  | State | Value | Sub |
  |-------|-------|-----|
  | `balance !== null && burn > 0` | `floor(balance / burn)` + « дн.» | `admin.analyticsRunwaySub` → «баланс 412 000 ₽ ÷ расход 3 100 ₽/день» |
  | `burn === null \|\| burn <= 0` | «—» | `admin.analyticsRunwayNoBurn` — «расхода нет» |
  | `balance === null` (ARTEMIDA failed) | «—» | `admin.analyticsRunwayNoBalance` — «баланс недоступен» |

  `burn === null` covers both "no costed orders" and "coverage below 100 % / fewer than 7 covered days"
  (D-14) — the meta line explains which. Runway is `Math.floor` of the **exact** burn, not the rounded
  display value.
- **`GET /balance` is called exactly once per render, only from this component.** A thrown error sets
  `balance = null` and is caught inside the component: the burn card still renders from DB data.
- **Empty:** meta no-orders + «—» on both cards («расхода нет» / «баланс недоступен» as applicable).
- **Error:** heading survives; body `text-sm text-muted` + `common.errorLoad`.
- **Deliberate non-alignment:** at `≥lg` this row is two half-width cards. Do **not** add a third card
  and do not stretch a card across two columns — an empty slot is honest, a fabricated metric is not.

### 6.5 «Продления и отток» block — three period cards

`RetentionCards({ period })`. Layout `GRID`. All cards `size="compact"`. Header meta:
`t('admin.analyticsWindowDays', { n: period })` → «30 дн. · МСК».

Block heading: `admin.analyticsRetentionCardsTitle` → «Продления и отток». The first card below it is
labelled `admin.analyticsRenewalRate` → «Доля продлений»; the two names must not be collapsed into one
key (the block counts expirations, the card counts renewals).

| Order | Label key | Value | Sub |
|-------|-----------|-------|-----|
| 1 | `admin.analyticsRenewalRate` — «Доля продлений» | `{pct}` or «—» | `admin.analyticsRenewalRateSub` — «продлено: {renewed} · истекало: {expiring}» |
| 2 | `admin.analyticsLogoChurn` — «Отток подписок» | `{pct}` or «—» | `admin.analyticsLogoChurnSub` — «отток: {churned} · активных на начало: {base}» |
| 3 | `admin.analyticsRevenueChurn` — «Отток выручки» | `{pct}` or «—» | `admin.analyticsRevenueChurnSub` — «потеряно {lost} ₽ MRR · база {base} ₽» |

- **Absolute counts are always visible in the sub**, even when the rate is «—» (D-08). The sub is never
  omitted.
- **Zero denominators (D-08/D-09):** `expiring === 0` → renewal «—» (not `0%`); `activeKeysAtStart === 0`
  → logo churn «—», sub still states the absolute count and «активных на начало: 0»;
  `mrrAtStart === 0` → revenue churn «—», sub still states «потеряно N ₽ MRR».
- **No color semantics.** A high churn rate is not an "error state" — value stays `text-foreground`.
  No arrow, no up/down icon, no trend delta (WoW/MoM is deferred ALR-01).
- **Empty (no expirations in the period):** all three «—» with the zero counts in the subs; no banner.
- **Error:** heading survives; meta dropped; body `text-sm text-muted` + `common.errorLoad`.

### 6.6 «Удержание по месяцам» — compact 6-MSK-month table

`ChurnTable()` (no props; ignores `?period`).

- **Window:** trailing **6 Europe/Moscow calendar months ending with the current month**, capped at the
  number of months since the first paid order, minimum 1 — identical derivation to `MrrWaterfall`, so
  the two 6-month blocks never disagree about how much history exists. A month with no expirations keeps
  its row (zeros, «—» for the rate).
- **Window label derived, never hardcoded:**
  `months.length === 1` → `t('admin.analyticsWaterfallWindowSingle')` («последний месяц · МСК»);
  `months.length >= 2` → `t('admin.analyticsWaterfallWindowMonths', { n: months.length })`
  («{n} мес. · МСК»). Both keys are **reused from Phase 7**.
- **Header:** block `h3` `admin.analyticsChurnTitle` («Удержание по месяцам») + the derived window label
  on the right (12px muted).

**Columns — exactly six, in this order:**

| # | Header key | Content | Alignment |
|---|------------|---------|-----------|
| 1 | `admin.analyticsTableMonth` (reused) | MSK month as `MM.YYYY` (e.g. «07.2026») | left, `text-muted` |
| 2 | `admin.analyticsColExpiring` — «Истекало» | integer | right, `tabular-nums` |
| 3 | `admin.analyticsColRenewed` — «Продлено» | integer | right, `tabular-nums` |
| 4 | `admin.analyticsColRenewalPct` — «Продление, %» | `{pct}` or «—» | right, `tabular-nums` |
| 5 | `admin.analyticsColChurned` — «Отток, шт.» | integer | right, `tabular-nums` |
| 6 | `admin.analyticsColLostMrr` — «Потеряно MRR, ₽» | `{₽}` (whole rubles; `0` for a churned bonus renewal) | right, `tabular-nums` |

- **Markup recipe** (visible table — no sr-only duplicate; this table *is* the accessible data):

  ```tsx
  <div role="region" tabIndex={0} aria-label={t('admin.analyticsChurnTitle')}
       className="overflow-x-auto rounded-2xl border border-line focus-visible:outline-2
                  focus-visible:outline-offset-2 focus-visible:outline-green">
    <table className="w-full min-w-[36rem] text-left text-sm">
      <caption className="sr-only">{t('admin.analyticsChurnCaption')}</caption>
      <thead className="bg-panel text-xs uppercase text-muted">
        <tr><th scope="col" className="px-4 py-3">…</th></tr>
      </thead>
      <tbody className="divide-y divide-line">
        <tr><th scope="row" className="px-4 py-3 font-normal text-muted">07.2026</th>
            <td className="px-4 py-3 text-right tabular-nums">…</td></tr>
      </tbody>
    </table>
  </div>
  ```

  First column is `<th scope="row">` (a row heading, unstyled: `font-normal text-muted`); every numeric
  cell is `<td className="px-4 py-3 text-right tabular-nums">`. Header cells are
  `px-4 py-3 font-semibold` (weight 600) — never `text-xs` on the numbers, only on the `thead`.
- **Rate cells with a zero denominator:** `expiring === 0` in a month → the «Продление, %» cell is «—»
  (never `0%`), while «Истекало», «Продлено», «Отток» and «Потеряно MRR» still render their real zeros.
- **No hover styling** (nothing is clickable). No zebra rows. No sort affordance.
- **Empty** (every rendered month has `expiring === 0` — no paid term has ever ended): heading + window
  label survive; body is a `rounded-2xl border border-line bg-panel p-4` panel with `text-sm text-muted` +
  `t('admin.analyticsChurnEmpty')`. No table, no header row. A single empty month **inside** a populated
  window is not an empty state — it keeps its row.
- **Error:** heading survives (window label dropped), body `text-sm text-muted` + `common.errorLoad`.
- **Loading:** `h-64 animate-pulse rounded-2xl bg-foreground/5` (`aria-hidden`).

### 6.7 Data contract the UI renders (pin the shapes, not the SQL)

```ts
loadLtv() → {
  grossHistorical: number | null; grossHistoricalPayers: number;
  grossPredictive: number | null; predictiveChurnRate: number | null;
  net: number | null; netPayers: number; coverageFrom: string | null; // "YYYY-MM-DD"
}

loadMargin(period: 7 | 30 | 90) → {
  grossMargin: number | null; marginPct: number | null; costPerKey: number | null;
  costedOrders: number; totalOrders: number;
}

loadBurnRunway() → {
  burnPerDay: number | null; burnCostedOrders: number; burnTotalOrders: number;
  burnDaysCovered: number;                 // DISTINCT MSK days with costed orders
  balance: number | null;                  // live GET /balance
  runwayDays: number | null;
  runwayReason: 'no-burn' | 'no-balance' | null;   // drives which sub-line renders
}

loadRetention(period: 7 | 30 | 90) → {
  renewalRate: number | null; renewedKeys: number; expiringKeys: number;
  logoChurnRate: number | null; churnedKeys: number; activeKeysAtStart: number;
  revenueChurnRate: number | null; lostMrr: number; mrrAtStart: number;
}

loadChurnTable() → {
  months: { month: string; /* "YYYY-MM-01" */ expiring: number; renewed: number;
            renewalRate: number | null; churned: number; lostMrr: number }[];
}
```

- Every loader is called from exactly one server component; no component imports another's result.
- **`null` is the only "unknown" sentinel.** «—» is a render decision in the component, never a number
  pushed from the loader. `0` is always a real zero and renders as `0 ₽` / `0` — never «—».
- Ratios stay **exact rationals** in the payload (no pre-rounded percentages); the component does the
  `× 100` and formatting. Nothing pre-formatted (no strings with «₽», no «%») crosses the loader boundary.
- **RSC leak surface:** these payloads contain cost and revenue aggregates only — no `providerCost` per
  order, no user ids, no API key, no raw provider error. Keep it that way (Pitfall 5, Phase 7).
- The current day is live where the metric is point-in-time (balance, LTV history); rollups are not
  re-read for the new blocks beyond what Phase 7 loaders already do.
