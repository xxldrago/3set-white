# Phase 10 — UI Design Contract

> Visual and interaction contract for the Phase 10 cohorts & retention surface.
> Generated by gsd-ui-researcher, verified by gsd-ui-checker.

**Extends `08-UI-SPEC.md` / `07-UI-SPEC.md` verbatim.** Phases 7–9 already fixed the design
system (light-only 3set tokens, hand-rolled Tailwind v4, pure SVG, Russian copy, no shadcn). Phase 10
**adds two cohort sections below the timing section** and changes nothing above them. Where this
document is silent, Phase 8 §5.2–§6.9 is the contract; where this document is explicit, it wins for
the new blocks only.

**Scope in one paragraph.** `/admin/analytics` gains, below the existing timing section (untouched):
a section «Когорты по регистрации» with a 12×12 registration-cohort matrix and channel tabs; and a
section «Когорты по первой оплате» with a 12×12 payer (revenue-retention) matrix, channel tabs and
device-count tabs. One new server component `CohortMatrix`, one new client component `CohortTabs`
(segmented control), zero new npm dependencies, zero new routes, no forms, no modals, no destructive
actions. Matrices are **independent of `?period`** (D-13) and render 12 cohorts × 12 relative months
(D-04). Empty cells render «—» (D-01, D-03); no zero-filling of gaps (D-01, D-05).

**Explicit non-goals (do not add):** a cohort snapshot/rollup table (deferred), drill-down into a cell's
user list (Phase 11), CSV export (EXT-06), alerts (ALR), a tariff (days) slice (deferred), a second
page or route, any chart beyond the matrix, any new color beyond the cell tint, any client-side data
fetching, any change to blocks above the new sections.

### Decisions applied

| Locked decision | How this contract implements it |
|-----------------|---------------------------------|
| **D-01** — registration cohort = MSK month of `User.createdAt`; retained if ≥1 paid key whose coverage (`paidAt + days`) intersects month M+N; trial keys excluded; gaps stay empty («—») | §6.2 matrix cell = retained users / cohort size; empty cell renders «—», never `0%`. |
| **D-02** — payer cohort month = MSK month of first paid order; membership fixed forever | §6.3 row header = first-paid MSK month; cohort size frozen at first render of that month. |
| **D-03** — revenue retention = cash of orders paid in month M+N ÷ cash of orders paid in M0, all orders of the cohort | §6.3 cell = revenue retention %; denominator is the cohort's M0 cash (never re-based). |
| **D-04** — 12 cohort months × 12 offsets (M0..M11), code constant | §6.2 / §6.3: exactly 12 rows and 12 columns; no truncation to "available" history beyond empty cells. |
| **D-05** — return after a gap stays empty; payer cohort never moves | Cell rendering: a gap month is «—»; the row keeps its original cohort month. |
| **D-06** — only paid keys count | Registration matrix excludes trial keys from retained counts; cohort size still includes all registered users of that month. |
| **D-07 / D-08 / D-09** — channel computed on the fly: referral > promo > organic | §6.4 channel tabs; channel label never persisted; priority referral > promo is fixed. |
| **D-10 / D-11 / D-12** — device bucket = first paid order's `devices`, buckets 1/2/3/4/5+, applies only to payer matrices | §6.5 device tabs appear only on the payer matrix; registration matrix has no device tabs. |
| **D-13** — matrices independent of `?period` | §6.1: matrices ignore `period`; only channel/device query params drive them. |
| **D-14** — tabs over one matrix (channel + device) | §6.4 / §6.5: one `CohortMatrix` per section; tabs are segmented controls above it. |
| **D-15** — cell = percent + absolute in parens, gradient background 0–100%, numbers always present | §6.2 / §6.3 cell anatomy; gradient stops §Color. |
| **D-16** — small cohorts shown as-is, no masking | No minimum-size threshold; small cohorts render with their real counts. |
| **D-17** — MSK month boundaries | §6.2 / §6.3 row and column labels are MSK months; no UTC. |

### Deviations from locked decisions

Recorded, not silently dropped. No locked choice is reversed.

| Item | State in Phase 10 | Why |
|------|-------------------|-----|
| **D-14 "tabs" wording** | Rendered as **segmented controls** (`role="group"` + `aria-pressed` buttons), not ARIA `tablist`/`tabpanel`. Same visual as `PeriodSelector`. | The project has no tab component and no tab keyboard-nav helper; reusing the proven segmented-control recipe keeps a11y and styling consistent (focus ring, 44px targets, lime active state). The matrix is not a "panel swap" — it is one table re-filtered, so `aria-pressed` is the honest semantics. |
| **D-15 cell absolute** | Registration cell absolute is `{retained}/{size}` (a ratio); payer cell absolute is the month's revenue `{₽}` (not a ratio), because revenue retention compares different monetary bases. | D-15 fixes "percent + absolute in parens" but not which absolute; the two matrices have different bases (users vs. money), so the absolute must differ to stay meaningful. |
| **D-04 12 cohorts** | Rows are the **trailing 12 MSK months ending with the current month**, not "the first 12 months of data". A young install shows fewer than 12 populated rows as empty matrices with «—». | "12 cohort months" reads as a fixed window in the UI; deriving the window from data age would make the matrix shape jump month to month and break column alignment. Empty rows are honest and keep the grid stable. |
| **D-07 channel on the fly** | Channel tabs are **client-side URL filters** (`?regCh`, `?payCh`, `?payDev`) that trigger a server re-render via `router.refresh()`, identical to `PeriodSelector`. No client data fetching. | Consistent with the existing period selector; the matrix stays a server component and the no-leak boundary (Pitfall 5) is preserved. |

## Color

**Tokens only** — same palette as Phase 7/8, no additions. No hex literal in any new component except
the cell tint stops below (which are derived from `--lime` and must be written as `rgba(183,255,69,α)`
with the literal justified by the token, identical to how Phase 7 writes `--lime`).

| Role | Token | Value | Usage |
|------|-------|-------|-------|
| Dominant (60%) | `--background` | `#f6f4ee` | Page background (inherited) |
| Secondary (30%) | `--panel` | `#ffffff` | Matrix container, tab group background, empty-state panel |
| Accent (10%) | `--lime` `#b7ff45` + `--foreground` `#0e1512` | — | See reserved list — **adds three items** (tab active state, cell tint ramp, focus ring already listed) |
| Brand support | `--green` `#0c4f36` | Focus outlines on tabs and the scroll region |
| Destructive | — | — | **None** — read-only page, no destructive action |

Supporting: `--line` `#e4dfd1` (borders, section rule, tab inactive border), `--muted` `#5b645e`
(labels, row headers, meta, column headers), `--foreground` `#0e1512` (percent, tab labels, values),
`--dim` / `--line-2` (not used).

**Accent is reserved for (Phase 7 list, extended):** active `AdminNav` pill, selected `PeriodSelector`
segment, waterfall «Новые» bars, sparkline area fill, focus rings, **active tab segment**
(`bg-foreground text-lime`, identical to `PeriodSelector`), and **the cohort-matrix cell tint ramp**
(0 → 32% opacity of `--lime` over the cell background, see below).

**Accent is NOT used for:** matrix percent/absolute text, row/column headers, tab inactive state, section
headings, section rules, empty-state panels, or any background block other than the cell tint.

**Cell tint ramp (D-15):** each populated cell gets an inline background
`linear-gradient(180deg, rgba(183,255,69,0.04), rgba(183,255,69, calc(v * 0.32)))` where `v` is the
cell value in `[0,1]`. Empty/`—` cells get **no tint** (`transparent`). The ramp is the only place a
gradient exists on this page; it is a tint, not a decoration, and it never carries information without
the number (D-15: numbers always present). Contrast: percent stays `--foreground` (≈17:1) and absolute
stays `--muted` (≥5.6:1) on the maximum tint (0.32 opacity lime over white ≈ 92% lightness), so no
text color change is needed at any tint level.

**Signal semantics (locked, inherited):** no red, no amber, no green/red pass-fail coloring. A 0%
retention cell is a number, rendered in `--foreground` with tint 0 (transparent), never greyed-out or
struck through. «—» cells are muted text on transparent background.

**Formatting rules:**
- **Registration cell:** `{pct}% ({retained}/{size})` — e.g. «42% (3/7)». `pct = retained / size × 100`,

  is «—» (no percent, no parens).
- **Payer cell:** `{pct}% ({revenue} ₽)` — e.g. «85% (12 000 ₽)». `pct = revenue / baseRevenue × 100`.
  When `baseRevenue === null` or `baseRevenue === 0` the whole cell is «—». Money via `Intl.NumberFormat('ru-RU')` + ` ₽`, whole rubles.
- **Cohort month (row header):** `MM.YYYY` («07.2026»), identical to `ChurnTable`/`MrrWaterfall`.

- **Offset headers:** `M0`..`M11` literals.
- **«МСК»** appears in the matrix caption and meta — month boundaries are Europe/Moscow.
- **«—»** is U+2014. Never `0`, never `0%`, never `N/A`, never blank.
- No raw provider error, HTTP status, SQL or English string ever reaches the DOM.

<AnalyticsSection title={t('admin.analyticsRegCohortTitle')}>

    <CohortTabs param="payDev" label={t('admin.analyticsCohortDevicesLabel')}

- The registration section has **channel tabs only** (D-12: no device slice for non-payers).
- The payer section has **channel tabs then device tabs**, stacked (`gap-2`), channel first.
- `?period` keeps its current normalization and header position; matrices read `regCh`/`payCh`/`payDev`
  from `searchParams` with defaults `'all'` and whitelist validation (anything else → `'all'`).
- **Suspense count:** page gains **2** new boundaries (one per matrix) → **15 total** (3 phase-7 + 5
  phase-8 + 5 phase-9 + 2 phase-10). Fallback is `ChartSkeleton className="h-64"` (matrix is table-shaped).

**Degradation:** each matrix resolves independently; a failure renders the block heading + meta + `text-sm
text-muted` + `common.errorLoad`. Tabs remain interactive (they are client components and do not depend on
the loader). A failure in one matrix never affects the other or any block above.

### 6.2 Registration cohort matrix — `CohortMatrix kind="registration"`

`CohortMatrix({ kind, channel })` (server component, no props beyond filters).

- **Data:** `loadRegistrationCohorts(channel)` → `{ cohorts: { month, size, retained: (number|null)[] }[] }`
  (12 cohorts, each `retained` has 12 entries; `null` where the offset month is not yet reachable or the
  cohort has no members).
- **Header:** block `h3` `admin.analyticsCohortRegMatrixTitle` + meta `admin.analyticsCohortMeta` on the
  right (12px muted), identical header recipe to all other blocks.
- **Caption:** `admin.analyticsCohortMatrixCaption` as `<caption className="sr-only">`.
- **Columns:** `admin.analyticsTableMonth` (month) · `admin.analyticsCohortSize` (size) · `M0`..`M11`.
  Exactly 14 columns. Header cells `px-4 py-3 font-semibold` (600), `text-xs uppercase text-muted`;
  offset headers centered, month/size left.
- **Row:** month cell `<th scope="row" className="px-4 py-3 font-normal text-muted whitespace-nowrap">`
  rendering `MM.YYYY`; size cell `<td className="px-4 py-3 text-right tabular-nums">` rendering the count.
- **Cell:** `<td className="px-2 py-2 text-center whitespace-nowrap">` with an inner `<div>` carrying the
  tint background and `rounded-lg px-2 py-1`:

  ```tsx
  <td className="px-2 py-2 text-center whitespace-nowrap">
    <div className="rounded-lg px-2 py-1"
         style={{ background: cell === null || size === 0
           ? 'transparent'
           : `linear-gradient(180deg, rgba(183,255,69,0.04), rgba(183,255,69,${(cell/size)*0.32}))` }}>
      {cell === null || size === 0
        ? <span className="text-muted">—</span>
        : <>
            <span className="text-xs font-semibold tabular-nums text-foreground">
              {pct.format((cell / size) * 100)}%
            </span>
            <span className="text-xs tabular-nums text-muted"> ({countFmt.format(cell)}/{countFmt.format(size)})</span>
          </>}
    </div>
  </td>
  ```

  `cell` here is the retained count. `size` is the cohort size.
- **Empty matrix** (every cohort size is 0): heading + meta survive; body is
  `rounded-2xl border border-line bg-panel p-4` with `text-sm text-muted` + `admin.analyticsCohortEmpty`.
  No table, no header row.
- **Partial:** a cohort with size > 0 but an empty offset renders «—» in that cell with no tint; the row
  stays. A cohort with size 0 renders «—» in every cell.
- **No hover, no zebra, no sort.** Read-only.

### 6.3 Payer (revenue) cohort matrix — `CohortMatrix kind="payer"`

`CohortMatrix({ kind, channel, deviceBucket })` (server component).

- **Data:** `loadPayerCohorts(channel, deviceBucket)` →
  `{ cohorts: { month, size, baseRevenue: number|null, revenue: (number|null)[] }[] }`.
  `size` = number of payers in the cohort (after channel/device filter); `revenue[offset]` = cash paid in
  that offset month by cohort members.
- **Header:** block `h3` `admin.analyticsCohortPayerMatrixTitle` + meta `admin.analyticsCohortMeta`.
- **Caption:** `admin.analyticsCohortMatrixCaption`.
- **Columns:** identical to §6.2 (month · size · M0..M11).
- **Cell:** same tint recipe, but the absolute is money and the ratio divides by `baseRevenue`:

  ```tsx
  {revenue === null || baseRevenue === null || baseRevenue === 0
    ? <span className="text-muted">—</span>
    : <>
        <span className="text-xs font-semibold tabular-nums text-foreground">
          {pct.format((revenue / baseRevenue) * 100)}%
        </span>
        <span className="text-xs tabular-nums text-muted"> ({money.format(Math.round(revenue))} ₽)</span>
      </>}
  ```

  Tint uses `(revenue / baseRevenue)` clamped to `[0,1]` for the alpha (a retention above 100% tints at
  the 32% cap — the number still shows the real percentage, e.g. «120%»).
- **M0 column** is the cohort's first paid month; its cell is always `100% ({baseRevenue} ₽)` when
  `baseRevenue > 0`, and «—» otherwise. This is the denominator and must be visually present.
- **Empty / partial** rules identical to §6.2.

### 6.4 Channel tabs — `CohortTabs`

`CohortTabs` is a **client component** (`'use client'`), the only client component this phase adds. It
mirrors `PeriodSelector` exactly in mechanism and styling.

```tsx
'use client';
import { usePathname, useRouter, useSearchParams } from 'next/navigation';
import { t } from '@/lib/i18n';

export default function CohortTabs({
  param, label, options, labels,
}: {
  param: string; label: string;
  options: readonly string[];
  labels: Record<string, string>;
}) {
  const router = useRouter();
  const pathname = usePathname();
  const searchParams = useSearchParams();
  const current = searchParams.get(param) ?? 'all';
  const active = options.includes(current) ? current : 'all';

  function choose(value: string) {
    const params = new URLSearchParams(searchParams.toString());
    params.set(param, value);
    router.replace(`${pathname}?${params.toString()}`);
    router.refresh();
  }

  return (
    <div className="flex flex-wrap items-center gap-2" role="group" aria-label={label}>
      <span className="text-xs text-muted">{label}</span>
      {options.map((value) => {
        const isActive = value === active;
        return (
          <button
            key={value}
            type="button"
            aria-pressed={isActive}
            onClick={() => choose(value)}
            className={
              isActive
                ? 'h-11 rounded-lg bg-foreground px-4 text-sm text-lime focus-visible:outline-2 focus-visible:outline-offset-2 focus-visible:outline-green'
                : 'h-11 rounded-lg border border-line px-4 text-sm text-foreground focus-visible:outline-2 focus-visible:outline-offset-2 focus-visible:outline-green'
            }
          >
            {labels[value] ?? value}
          </button>
        );
      })}
    </div>
  );
}
```

- **Channel options/labels:** `all` → `admin.analyticsCohortTabAll` («Все»), `referral` →
  `admin.analyticsCohortTabReferral`, `promo` → `admin.analyticsCohortTabPromo`, `organic` →
  `admin.analyticsCohortTabOrganic`.
- **Device options/labels:** `all` → «Все», `1`,`2`,`3`,`4`,`5+` → the digit literals.
- **Active state** is read from the URL on every render; an unknown value falls back to `'all'` (never
  crashes, never shows an empty tab bar).
- **Tabs do not depend on data:** they render before the `Suspense` boundary and stay interactive during
  loading and on error.

  <table className="w-full min-w-[60rem] text-left text-sm">
    <caption className="sr-only">{t('admin.analyticsCohortMatrixCaption')}</caption>
    <thead className="bg-panel text-xs uppercase text-muted">…</thead>
    <tbody className="divide-y divide-line">…</tbody>

- **`min-w-[60rem]`** (960px) guarantees the 14 columns never wrap; below that the region scrolls.
- **First column is `<th scope="row">`** (month), second is `<th scope="col">` (size) — wait, size is a
  column header, so it is `<th scope="col">`. Offset headers are `<th scope="col">`.
- **No sr-only twin table** — this table is the accessible data, identical to `ChurnTable`.
- **Loading:** `ChartSkeleton className="h-64"` (`aria-hidden`) inside the block's `Suspense`.
- **Error:** heading + meta survive; body `text-sm text-muted` + `common.errorLoad` inside one
  `rounded-2xl border border-line bg-panel p-4` panel.

### 6.7 Data contract the UI renders (pin the shapes, not the SQL)

```ts
loadRegistrationCohorts(channel: 'all' | 'referral' | 'promo' | 'organic') → {
  cohorts: { month: string; /* "YYYY-MM-01" MSK */ size: number;
             retained: (number | null)[]; /* length 12, null = not reachable / no data */ }[];
}

loadPayerCohorts(channel, deviceBucket) → {
  cohorts: { month: string; size: number;
             baseRevenue: number | null; /* cash of M0, the denominator */
             revenue: (number | null)[]; /* length 12, cash per offset month */ }[];
}
```

- `channel === 'all'` applies no filter; deviceBucket `'all'` applies no filter.
- `null` is the only "unknown" sentinel. `0` is a real zero (a cohort of size 0, a month with zero
  revenue) and renders as `0` / `0 ₽`, never «—».
- Ratios stay exact rationals in the payload; the component does the `× 100` and formatting.
- **RSC leak surface:** payloads contain cohort aggregates only — no `providerCost` per order, no user ids,
  no API key, no raw provider error. Keep it that way (Pitfall 5).
- Cohort month list is always 12 entries (trailing 12 MSK months), even when data is sparse; missing
  cohorts have `size: 0`.

| Breakpoint | Matrix | Tabs |

Page rhythm unchanged: page `gap-6`, section body `gap-4`, matrix `rounded-2xl border border-line`,
tab group `gap-2`. Admin shell still supplies `max-w-6xl`, `px-6 py-12 sm:px-16`.

### 6.9 Accessibility

- **Matrix:** real `<table>` with `<caption class="sr-only">`, `scope="col"` on all 14 headers,
  `scope="row"` on the month cell. Not `aria-hidden`; no sr-only twin.
- **Scroll region:** `role="region"`, `tabIndex={0}`, `aria-label` = the block heading; visible focus
  ring `outline-green` — identical to `ChurnTable` / `ErrorTable`.
- **Tabs (segmented controls):** `role="group"` + `aria-label` on the container; each button
  `aria-pressed`. Focus ring `outline-green`. Keyboard: Tab moves between buttons, Enter/Space activates
  (native button behaviour — no custom key handler needed).
- **Unknown values:** «—» announced verbatim; the meta line states the window; no per-cell explanation
  (the column header + row header give context).
- **Headings:** monotone — `h2` page → `h3` first-screen blocks → `h2` new sections → `h3` matrix blocks.
  No `h4`.
- **Contrast:** percent `--foreground` (≈17:1), absolute `--muted` (≥5.6:1) even on the 32% tint;
  empty cell «—» `--muted`. No lime text anywhere in the new sections except the active tab label on
  `--foreground` background (inherited, already compliant).
- **Motion:** only the existing `animate-pulse` skeletons. The cell tint is a static inline style — no
  transition, so `prefers-reduced-motion` needs no handling.
