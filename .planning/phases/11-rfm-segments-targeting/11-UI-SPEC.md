# Phase 11 — UI Design Contract

> Visual and interaction contract for the Phase 11 RFM segments & targeting surface.
> Generated by gsd-ui-researcher, verified by gsd-ui-checker.

**Extends `10-UI-SPEC.md` / `08-UI-SPEC.md` / `07-UI-SPEC.md` verbatim.** Phases 7–10 already fixed
the design system (light-only 3set tokens, hand-rolled Tailwind v4, pure SVG, Russian copy, no shadcn).
Phase 11 **adds one new admin page `/admin/segments`, a nav item, a drill-down filter on `/admin/users`,
and an audience selector in `BroadcastComposer`** and changes nothing in the analytics sections. Where this
document is silent, Phase 8 §5.2–§6.9 and Phase 10 §6.1–§6.9 are the contract; where explicit, this
document wins for the new surfaces only.

**Scope in one paragraph.** A new page `/admin/segments` (administrator + manager) renders seven neutral
segment cards (trial-only, new payer, active, at-risk, churned, sleeping, VIP) each showing its size and
a short definition, followed by a thresholds form (five numeric inputs + save) and an empty/error state.
The cards link to `/admin/users?segment=<name>` (drill-down). `/admin/users` gains a `?segment=` filter,
a segment badge column, and (only in filtered view) three RFM columns (Recency days, paid orders, spent ₽).
`BroadcastComposer` gains an «Аудитория» dropdown («Все получатели» + seven segments with sizes) and a
recipient-count preview fetched from `GET /api/admin/segments/:name/count`. No new npm dependency, no
shadcn, no new color, no destructive action, no modal.

**Explicit non-goals (do not add):** a second analytics page or route, CSV export (EXT-06), alerts (ALR),
per-user drill-down beyond the filtered list, RFM quantile scoring (deferred), chargeback accounting in
Monetary, a cron trigger button in the UI beyond the save-and-recompute flow, any red/amber/green
pass-fail coloring on segment cards, any chart, any client-side data fetching beyond the count preview.

### Decisions applied

| Locked decision | How this contract implements it |
|-----------------|---------------------------------|
| **D-05** — rule-based named segments, not RFM quantiles | §6.2 cards show a one-line rule ("последняя оплата ≤ 30 дн.") so the admin sees the definition, not a score. |
| **D-06** — seven segments in priority order | §6.2 renders exactly seven cards in the locked order: trial-only, new payer, VIP, active, at-risk, churned, sleeping. (VIP is moved visually after new payer to keep the priority order, but the card list follows D-06 order.) |
| **D-07** — thresholds in `Setting` (key/value), no migration | §6.3 form reads/writes the five `rfm.threshold.*` keys; inputs are number fields with the D-14 defaults as placeholders. |
| **D-08** — admin edits thresholds on `/admin/segments` | §6.3: five inputs + «Сохранить»; success copy states the recompute was triggered. |
| **D-09** — VIP = top 5% by Monetary (dynamic) | §6.2 VIP card shows «топ 5% по тратам» as its rule; the threshold input edits `rfm.threshold.vipPercent`. |
| **D-14** — drill-down via `/admin/users?segment=` | §6.4 users page reads `?segment=`, filters rows, shows a removable badge. |
| **D-15** — count endpoint `GET /api/admin/segments/:name/count` | §6.5 composer calls it on audience change and shows «Получателей: {n}». |
| **D-16** — broadcast body `{ body, segment? }`, default `'all'` | §6.5 composer sends `segment` only when a non-«all» audience is chosen; `segment` omitted → `'all'`. |
| **D-17** — dropdown in `BroadcastComposer` | §6.5: native `<select>` (not a segmented control) with «Все получатели» + seven segments and sizes. |
| **D-18** — `/admin/segments` page + `AdminNav` item | §6.1 adds the page; §Design System / Component Inventory note the new nav section `segments`. |
| **D-19** — neutral tokens, segments differ by icon/label not color | §Color: cards use `--panel` surface + `--line` border; no per-segment color. Accent only for active/selected. |
| **D-20** — MSK boundaries | §6.6 / §Copywriting: all "days ago" and recompute timestamps are MSK; copy says «МСК» where a day boundary matters. |

### Deviations from locked decisions

Recorded, not silently dropped. No locked choice is reversed.

| Item | State in Phase 11 | Why |
|------|-------------------|-----|
| **D-06 segment order** | Cards render in the D-06 priority order, but the **nav dropdown and audience `<select>`** list them in a stable alphabetical-ish display order: trial-only, new payer, active, at-risk, churned, sleeping, VIP (VIP last, because it is the "premium" bucket). | D-06 fixes matching priority, not display order. Keeping VIP last in pickers avoids a manager accidentally targeting the premium bucket first; the card grid keeps the locked priority order. |
| **D-14 "no new page"** | Drill-down reuses `/admin/users` but adds a **segment badge + clear link** and **three RFM columns in filtered view only**. | D-14 forbids a new page, not new columns. The RFM columns are the whole point of a segment drill-down; showing them only when filtered keeps the base users table width stable. |
| **D-17 native `<select>`** | Audience picker is a native `<select>` rather than the segmented-control recipe. | Seven segments + «Все» = 8 options; a segmented control would overflow on mobile and wrap to 4 rows. A native select stays one line, is keyboard-accessible by default, and matches the form inputs in §6.3. |

### 6.1 Page composition — `/admin/segments`

New route `app/admin/segments/page.tsx`, guard `requireRole('administrator', 'manager')` (same as analytics).
`export const dynamic = 'force-dynamic'`.

```tsx
<section className="flex flex-col gap-6">
  <header className="flex flex-wrap items-center justify-between gap-3">
    <h2 className="text-xl font-semibold text-foreground">{t('admin.segmentsTitle')}</h2>
    <span className="text-xs text-muted">{t('admin.segmentsMeta')}</span>
  </header>

  <Suspense fallback={<CardsSkeleton count={7} />}>
    <SegmentCards />
  </Suspense>

  <AnalyticsSection title={t('admin.segmentsThresholdsTitle')}>
    <span className="text-xs text-muted">{t('admin.segmentsThresholdsMeta')}</span>
    <SegmentThresholdsForm />
  </AnalyticsSection>
</section>
```

- **`CardsSkeleton`** is the existing one from `page.tsx` (8-up? no — 7 cards). Reuse with `count={7}`; the
  grid collapses to 1 column on mobile, so 7 skeletons stack — acceptable.
- **Suspense count:** 1 new boundary (segment cards). Thresholds form is a client component and does not
  suspend.
- **Degradation:** `SegmentCards` failure renders the page title + meta + `text-sm text-muted` +
  `common.errorLoad` in a bordered panel; the thresholds form still renders (it reads `Setting` directly
  and is independent). A thresholds save failure shows `admin.segmentsSaveError` inline and leaves the
  inputs editable.

### 6.2 Segment cards — `SegmentCards`

Server component, no props. Calls `loadSegments()` → `{ segments: { name, size, chatCount, rule }[] }`
(7 entries in D-06 priority order).

- **Grid:** `grid grid-cols-1 gap-4 sm:grid-cols-2 lg:grid-cols-4`. Seven cards → 4 + 3 on `lg`, 2-col
  pairs on `sm`, stacked on mobile. The last row is left-aligned (no centering, no stretching).
- **Card anatomy** (each card is a `<Link href={/admin/users?segment=${name}}>`):

  ```tsx
  <Link
    href={`/admin/users?segment=${name}`}
    className="flex flex-col gap-3 rounded-2xl border border-line bg-panel p-6 transition-colors hover:bg-foreground/5 focus-visible:outline-2 focus-visible:outline-offset-2 focus-visible:outline-green"
  >
    <div className="flex items-center gap-3">
      <span className="inline-flex h-9 w-9 items-center justify-center rounded-lg bg-foreground/5 text-foreground">
        <Icon className="h-5 w-5" aria-hidden="true" />
      </span>
      <h3 className="text-base font-semibold text-foreground">{label}</h3>
    </div>
    <p className="text-2xl? no — text-xl font-semibold tabular-nums text-foreground">{size}</p>
    <p className="text-xs text-muted">{t('admin.segmentSizeSub', { n: size })}</p>
    <p className="text-sm text-muted">{rule}</p>
    <p className="text-xs text-muted">{t('admin.segmentChatSub', { n: chatCount })}</p>
  </Link>
  ```

  Wait — the count appears twice (big number + sub). Drop the redundant sub: keep the big number as the
  size, and the sub-line as «с Telegram: {n}» only. The «пользователей» word is conveyed by the card
  context; do not render «{n} пользователей» next to the same number. Concretely:

  - Big number: `size` (`text-xl font-semibold tabular-nums`).
  - Sub-line 1: `admin.segmentChatSub` → «с Telegram: {n}» (`text-xs text-muted`).
  - Sub-line 2: the rule string (`text-sm text-muted`).

- **Icon per segment** (lucide, `h-5 w-5`, `aria-hidden`, no per-segment color — all `text-foreground`):

  | Segment | Icon |
  |---------|------|
  | trial-only | `Sprout` |
  | new payer | `Sparkles` |
  | VIP | `Crown` |
  | active | `Activity` |
  | at-risk | `AlertTriangle` |
  | churned | `UserX` |
  | sleeping | `Moon` |

  Icons are decorative; the label is the accessible name. Do not color-code by icon.

- **Empty (no `user_rfm` rows):** `SegmentCards` returns `null` and the page renders `admin.segmentsEmpty`
  in a `rounded-2xl border border-line bg-panel p-4` panel with `text-sm text-muted`. The thresholds form
  still renders below.
- **Partial (some segments zero):** the card renders with `0` and stays a link (a zero-size segment still
  has a definition; clicking shows the empty filtered list).
- **No hover color change beyond `bg-foreground/5`** (inherited). No per-segment accent, no badge.

### 6.3 Thresholds form — `SegmentThresholdsForm`

### 6.5 Broadcast composer — audience selector

`BroadcastComposer` (client component) gains, above the textarea:

```tsx
<div className="flex flex-wrap items-center gap-3">
  <label htmlFor="broadcast-audience" className="text-sm font-semibold">{t('admin.broadcastAudience')}</label>
  <select
    id="broadcast-audience"
    value={audience}

      </option>
    ))}
  </select>
  <span className="text-sm text-muted" role="status" aria-live="polite">
    {countLoading ? t('admin.broadcastCountLoading')
      : countError ? t('admin.broadcastCountError')
      : t('admin.broadcastRecipients', { n: count })}
  </span>

```

- **`segments`** is passed as a prop from the server-rendered broadcast page (so the composer stays a client
  island without fetching the list itself). Shape: `{ name: string; size: number }[]` in D-06 display order.
- **Count preview:** when `audience` changes, call `GET /api/admin/segments/${audience}/count` (or

- **Send CTA disabled** when `!trimmed` OR `count === 0` OR `countLoading`. The confirm dialog body reuses
  `admin.broadcastConfirmBody` and states the recipient count is the previewed number.
- **No new dependency.** Native `<select>` only; no combobox library.
- **`AdminConfirmPanel`** payload is updated to include `segment`; its `url` stays `/api/admin/broadcast`.

### 6.6 Data contract the UI renders (pin the shapes, not the SQL)

```ts
loadSegments() → {
  segments: { name: SegmentSlug; size: number; chatCount: number }[]; // 7 entries, D-06 priority order
}

// thresholds (read by the server page, passed to the client form)
loadThresholds() → {
  newPayerDays: number; activeDays: number; atRiskDays: number;
  churnedDays: number; vipPercent: number;
}

// users drill-down
loadAdminUsersTable(segment?: SegmentSlug) → UserRow[] // existing shape + segment, recencyDays,
//   frequency, monetary (monetary: number | null)

// count preview
GET /api/admin/segments/:name/count → { count: number } // users in segment with chatId != null;
//   :name === 'all' → all users with chatId != null
```

- `SegmentSlug` = `'trial-only' | 'new payer' | 'VIP' | 'active' | 'at-risk' | 'churned' | 'sleeping'` (use
  the slug form the backend stores in `user_rfm.segment`; the UI maps slugs to localized labels via a
  literal switch, never a dynamic key — same rule as Phase 9 funnel labels).
- **`null` is the only "unknown" sentinel.** Monetary is `null` for trial-only users (D-13); recencyDays is
  never null (D-01/D-13). «—» is a render decision in the component.
- **RSC leak surface:** payloads contain aggregates and per-user RFM scalars only — no `providerCost` per
  order, no API key, no raw provider error, no email beyond what the users table already shows. Keep it
  that way (Pitfall 5).

### 6.8 Accessibility

- **Segment cards:** each card is a single `<Link>` with the segment label as its accessible name (the count
  and rule are `aria-hidden`? No — keep them in the accessibility tree as supporting text; the link's
  accessible name is the `<h3>` label via heading-in-link convention). Focus ring `outline-green`.
  No `role="button"` (it is a link).
- **Threshold inputs:** each has a visible `<label htmlFor>`; `aria-describedby` points at the helper text
  when present. Focus ring `outline-green`. Validation errors are announced via `aria-live="polite"` on the
  helper span.
- **Users table scroll region (filtered view):** `role="region"`, `tabIndex={0}`, `aria-label` =
  `admin.searchLabel` (or a new `admin.usersSegmentTableLabel` if the executor prefers — keep it simple and
  reuse `admin.searchLabel`). Visible focus ring `outline-green`.
- **Badge clear link:** `×` with `aria-label={admin.usersSegmentClear}`; focusable, `outline-green`.
- **Audience `<select>`:** native, keyboard-accessible by default; `aria-label` not needed (visible label).
  Count preview uses `role="status" aria-live="polite"`.
- **Headings:** monotone — `h2` page → `h3` card titles / block titles. No `h4`.
- **Contrast:** all new text is `--muted` (≈6.1:1 on `--panel`) or `--foreground` (≈17:1). No lime text,
  no `--dim` text. Accent appears only on primary button labels on `--foreground` background (inherited,
  already compliant).
- **Motion:** only the existing `animate-pulse` skeletons. No transitions on counts or table rows, so
  `prefers-reduced-motion` needs no handling.
