## Критерии degraded и write-guard

### 1. Что считать degraded-событием?

| Option | Description | Selected |
|--------|-------------|----------|
| Сбой вызова ARTEMIDA | timeout, 5xx после p-retry, 429 с исчерпанными ретраями, 401/402 | ✓ |
| Любой неполный ответ | включая подозрительно пустые/частичные ответы | |
| Только повлиявшее на метрику | событие на уровне источник+день+метрика | |

**User's choice:** Сбой вызова ARTEMIDA
**Notes:** Явно отвергнут «любой пустой ответ» — защита от ложных флагов.

### 2. Поведение rollup при degraded

| Option | Description | Selected |
|--------|-------------|----------|
| Защита здоровых + флаг первой записи | здоровый день не перезаписывается; первая запись degraded-дня пишется с событием | ✓ |
| Пропускать день полностью | дыра в графике, только событие | |
| Подставлять last-known | синтетические цифры без дыр | |

**User's choice:** Защита здоровых + флаг первой записи

### 3. Кто повторяет сбор за degraded-день

| Option | Description | Selected |
|--------|-------------|----------|
| Авто-ретрай 3 дня + backfill | ночной rollup перепроверяет последние 3 MSK-дня с открытым событием | ✓ |
| Только ручной backfill | закрытие вручную | |
| Не ретраить | день остаётся помеченным навсегда | |

**User's choice:** Авто-ретрай 3 дня + backfill

### 4. Когда показывать затронутость метрики

| Option | Description | Selected |
|--------|-------------|----------|
| Любое событие → бейдж + счётчик | максимальная честность, минимум логики | ✓ |
| Порог >5% дней | меньше шума, мелкие пропуски невидимы | |
| Только полные провалы | частичные исключения не выделяем | |

**User's choice:** Любое событие → бейдж + счётчик

## Подача дельт WoW/MoM

### 1. Где показывать дельту

| Option | Description | Selected |
|--------|-------------|----------|
| Внутри каждой карточки | расширяем `MetricCard` пропами `delta`/`quality` | ✓ |
| Отдельный блок сравнения | таблица «метрика / сейчас / было / Δ%» | |
| Только ключевые KPI | hero-карточки, остальные без дельт | |

**User's choice:** Внутри каждой карточки

### 2. Какое окно сравнения

| Option | Description | Selected |
|--------|-------------|----------|
| Авто по периоду | 7→WoW, 30→MoM, 90→предыдущие 90 дней | ✓ |
| Явный переключатель WoW/MoM | отдельный контрол | |
| Оба сразу | две дельты на карточке | |

**User's choice:** Авто по периоду

### 3. Нулевая база

| Option | Description | Selected |
|--------|-------------|----------|
| «—» + подпись «нет базы» | абсолютная дельта остаётся | ✓ |
| «новое» | не подходит для churn и подобных | |
| Скрыть | карточка без строки сравнения | |

**User's choice:** «—» + подпись

### 4. Неполный текущий день

| Option | Description | Selected |
|--------|-------------|----------|
| Только завершённые дни | сегодняшний MSK-день исключён из обоих окон | ✓ |
| Сравнение по прошедшему времени | точнее, дороже | |
| Пометить `partial` | считать сегодня, но помечать | |

**User's choice:** Только завершённые дни
**Notes:** Это прямая реакция на ловушку из research: `windowStartDay` включает сегодня, и «сегодня против целой недели» даёт ложное падение.

## Захват кликов и IP

### 1. Где хранить клики generic-промокодов

| Option | Description | Selected |
|--------|-------------|----------|
| Обобщить `referral_clicks` | `ownerUserId` nullable + `promoCodeId`/`kind` | ✓ |
| Отдельная `promo_clicks` | две таблицы и UNION в воронке | |

**User's choice:** Обобщить `referral_clicks`
**Notes:** Одна таблица — одна воронка click → register → pay для всех кодов.

### 2. Что считать одним кликом

| Option | Description | Selected |
|--------|-------------|----------|
| Час по `ipHash`, как сейчас | сохраняет семантику `recordClick` | ✓ |
| Сессия 24ч (cookie) | точнее, требует cookie/consent | |
| Без дедупа | раздутые цифры | |

**User's choice:** Час по `ipHash`

### 3. Retention кликов и `ipHash`

| Option | Description | Selected |
|--------|-------------|----------|
| 13 месяцев + автоочистка | ночной cron удаляет старое | ✓ |
| Бессрочно | PII копится | |
| Без `ipHash` | нет дедупа | |

**User's choice:** 13 месяцев + автоочистка

### 4. Где фиксируем хеш IP аккаунта

| Option | Description | Selected |
|--------|-------------|----------|
| Регистрация + trial claim | `signupIpHash` + `trialIpHash` | ✓ |
| Только регистрация | повторный trial с того же IP не виден | |
| Каждый логин | уже трекинг сессий, не fraud-сигнал | |

**User's choice:** Регистрация + trial claim
