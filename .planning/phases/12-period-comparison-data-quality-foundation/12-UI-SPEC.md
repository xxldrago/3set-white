# Phase 12 — UI Design Contract

> Visual and interaction contract for the Phase 12 period-comparison & data-quality admin analytics
> surface. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

**Extends the shipped Phase 7/8 contracts** (`.planning/milestones/v1.1-phases/07-analytics-foundation-revenue-metrics/07-UI-SPEC.md`, `…/08-unit-economics-retention/08-UI-SPEC.md`) with exactly one addition: the optional `delta` + `quality` props on `MetricCard`. The phase must not invent a new visual language — the delta row and the quality badge are written with the existing token set, type scale and component recipes.

**Scope in one paragraph.** Phase 12 renders, inside the existing `/admin/analytics` blocks, the WoW/MoM delta row inside metric cards that have a comparable base, and the degraded-data quality badge (`данные неполные (N)`) when the window excluded events. Comparison windows are derived in pure modules (`lib/analytics/windows.ts`, `lib/analytics/compare.ts`); the card renders what it is given.

**Explicit non-goals (do not add):** a new WoW/MoM toggle (D-02 locks `?period`), new colors or type sizes, new i18n languages, a separate `/admin/data-quality` page (deferred), alerts UI (Phase 13), CSV/dictionary (Phase 16).

## Surface & Interaction Contract

### Comparison windows & `?period` mapping (restated for the UI)

- `?period=7` → current = the previous 7 complete MSK days; base = the 7 before → WoW. Delta baseline label: `к прошлой неделе`.
- `?period=30` → current = the previous MSK calendar month; base = the month before → MoM. Baseline: `к прошлому месяцу`.
- `?period=90` → current = the previous 90 days; base = the 90 before → `к прошлым 90 дням`.
- Both windows exclude today's incomplete MSK day (D-04); upper bound is exclusive (`lt endExclusive`).
- No new toggle — `PeriodSelector` (7/30/90) is reused unchanged; it already carries the selected
  segment via `aria-pressed`.

### MetricCard delta anatomy (D-01 — the core contract)

**Props:**

```ts
delta?: MetricDelta;
quality?: MetricQuality;
```

```ts
export type MetricDelta =
  | { status: 'ok'; abs: number; pct: number | null; base: number; current: number }
  | { status: 'no-base'; abs: number; pct: null; reason: 'zero' | 'absent' }
  | { status: 'incomparable'; reason: 'degraded-base' | 'degraded-current' | 'coverage' };

export interface MetricQuality {
  /** Count of excluded events inside the comparison window. */
  excluded: number;
  /** Event-level detail for the badge tooltip (raw tokens, verbatim). */
  events?: Array<{ day: string; source: string; reason: string }>;
}
```

**Delta row — visual anatomy (shared by `hero` / `default` / `compact`):**

```
[ sign + abs + " ₽" ]   [ sign + pct + "%" ]   [ baseline label ]
```

- Container: `flex flex-wrap items-baseline gap-x-2 gap-y-1`.
- Absolute cell: `text-sm font-semibold tabular-nums text-foreground`; content = explicit sign
  (`+` when delta > 0, `−` when < 0, `0` when equal — minus via Intl) + Intl number + ` ₽`.
- Percent cell: same class string; content = explicit sign + percent (`+`/`−`, max one fractional
  digit) + `%`; renders `—` when the base is empty (no-base) or when incomparable.
- Baseline cell: `text-xs text-muted`; content = localized baseline label or `—`.

**Per-status rendering (prescriptive):**

| Status | Delta row content | Notes |
|--------|-------------------|-------|
| `ok` | abs + sign + magnitude; pct + sign; baseline label (`к прошлой неделе` / `к прошлому месяцу` / `к прошлым 90 дням`). | Normal case. |
| `no-base` | abs rendered (semibold foreground); pct cell renders `—`; baseline cell renders `t('admin.analyticsDeltaNoBase')` = «нет базы». | D-03: absolute delta stays visible; percent never `∞%`/`0%`-for-no-data. |
| `incomparable` | Single muted marker cell: `t('admin.analyticsDeltaIncomparable')` = «сравнение недоступно» — no abs, no pct, no baseline. | D-05: number withheld; never a fake `0`. |

**Placement & vertical rhythm per size:**

- `default` / `compact` (vertical stack, `CARD` = `flex flex-col gap-2 rounded-2xl border border-line p-6`): DOM order label → value → **delta** → sub. Delta row is a conditional child (absent → identical output to today).
- `hero` (horizontal at `sm+`, `sm:items-end sm:justify-between`, vertical below): value right-aligned; delta row rendered after the value inside a conditional right column `<div className="flex flex-col items-end gap-1">` wrapping the value + delta row; when `delta` is absent the bare value span renders (zero behavioural delta). Delta row right-aligned.

**Mobile (375px):** delta row keeps `flex-wrap items-baseline gap-x-2 gap-y-1`; the baseline cell may
wrap to its own line; nothing truncates or overflows horizontally; abs+pct pair never splits from the
baseline semantically (wrap only moves the trailing baseline).

### Quality badge (D-10)

- Rendered when `quality.excluded > 0`; copy `t('admin.analyticsDataIncomplete', { n })` →
  «данные неполные (N)».
- **Placement:** sub-row slot (the `sub` position in `MetricCard`), rendered before any existing sub
  line; pill styling `inline-flex items-center rounded-lg border border-line bg-panel px-2
  py-1 text-xs text-muted`.
- **Size:** `text-xs` (12px) / weight 400 / muted — same micro-label family as subs and legends; pill
  padding per class string above.
- **Tooltip vs inline:** badge text (count) is inline and always visible; reason + event list live in
  the badge's native `title` attribute (per-event lines: `{day} · {source}: {reason}` with raw reason
  tokens verbatim, mirroring the ErrorTable raw-code precedent). No custom JS tooltip, no new dependency.
- **Touch:** badge is informational, not interactive — no tap action; always-visible inline pill means
  the count is never hover-only. Deferred: event drill-down page.
- No threshold — any excluded event in the window flags the card.

### Accessibility

- Delta row is plain visible text (sign + magnitude + baseline); numbers carry `tabular-nums`; no
  icon-only encoding, no color-only encoding of sign.
- Badge is plain visible text (`данные неполные (N)`), not icon-only; sub-line content is real DOM text,
  so screen readers and touch users both receive it without tooltip interaction.
- Focus: no new interactive elements are introduced by this phase; existing focus contract
  (`focus-visible:outline-2 focus-visible:outline-offset-2 focus-visible:outline-green`) is unchanged.
- Contrast verified against real tokens: `--muted` `#5b645e` on `--panel` / `--background` ≈ 5.6–6.1:1
  (safe at 12–14px); `--foreground` `#0e1512` on `--panel` ≈ 17:1; `--dim` never used for text/marks.

**Accent reserved for — explicit list, never "all interactive elements":**

1. Active `PeriodSelector` segment — `bg-foreground text-lime`.
2. Active `AdminNav` pill — `bg-foreground text-lime`.
3. Waterfall «Новые» bars — `fill-lime` with `stroke-green` hairline.
4. Sparkline area fill — `fill-lime` at `fillOpacity={0.35}`.
5. Focus rings on this page's controls — `outline-green`.

**Accent is NOT used for:** delta rows, badge pills, card labels, values, borders, table headers,
axis text, error copy, legend labels, net-change markers.

**Signal semantics (locked):** no red/green semantic coloring. The delta row is **neutral** — sign is
carried solely by the explicit `+` / `−` character and magnitude in neutral tokens; no hue encodes
direction. This is a deliberate Phase 12 decision: deltas are comparisons, not sentiment, and the
neutral treatment keeps them grayscale-safe and consistent with the repo's "no red/green semantics"
constraint.

**Destructive:** none.
