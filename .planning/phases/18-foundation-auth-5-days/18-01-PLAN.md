Add all dependencies from RESEARCH.md Standard Stack (flutter_riverpod, flutter_secure_storage, dio, app_links, connectivity_plus, logger, freezed_annotation, json_annotation, jwt_decoder, build_runner, freezed, json_serializable).     2. **Core models** (`auth_models.dart`): Define `TokenPair`, `User`, `LoginRequest`, `RegisterRequest` as freezed classes with JSON serialization. Include `copyWith`, `fromJson`/`toJson`.

    3. **Secure storage wrapper** (`secure_storage.dart`): Singleton `FlutterSecureStorage` with Android Keystore (biometric options: `enforceBiometrics: false`, custom prompt title/subtitle) and iOS Keychain (`first_unlock_this_device`, `biometryCurrentSet`).

    4. **TokenStore** (`token_store.dart`): CRUD for access/refresh tokens + userId. `getAccessToken()` uses biometric read options (triggers Face ID/Touch ID/Android biometric). `getRefreshToken()` reads without biometric. `saveTokenPair()` writes all three atomically. `clearAll()` deletes all. `hasTokens()` checks both exist.

    5. **DioClient + AuthInterceptor** (`dio_client.dart`, `auth_interceptor.dart`): Configured Dio with baseUrl `https://dash.3set.online`, 15s connect / 30s receive timeouts. Interceptor: onRequest attaches `Authorization: Bearer <accessToken>` from TokenStore; onError 401 → single refresh via `/api/mobile/auth/refresh` using refresh token → retry original request once; queue concurrent 401s during refresh (`_isRefreshing` + `_waitingRequests` pattern from RESEARCH.md Pattern 1). Logging interceptor in debug only.

    6. **AuthState + AuthNotifier** (`auth_state.dart`, `auth_notifier.dart`): Freezed `AuthState` with `unauthenticated`, `authenticated(tokens, user)`, `loading`, `error(message)`. `AsyncNotifierProvider` with `build()` performing session restore: read tokens from TokenStore → if missing return unauthenticated → else validate via `GET /api/mobile/subscription` → if 200 return authenticated → if 401 try refresh token → if refresh succeeds validate new token → else clear storage and return unauthenticated. Methods: `login(email, password)`, `register(email, password)`, `logout()`, `startTelegramAuth()` (stub for now).

    7. **BiometricGate** (`biometric_gate.dart`): Riverpod provider with `WidgetsBindingObserver` listening for `AppLifecycleState.resumed`. On resume, if tokens exist, call `TokenStore.getAccessToken()` (triggers biometric). If biometric fails/cancels → clear storage + set unauthenticated.

    8. **ConnectivityService** (`connectivity_service.dart`): Wraps `Connectivity().onConnectivityChanged.distinct()` stream, exposes `Stream<ConnectivityResult>` for ping cache invalidation (Phase 19).

    9. **DeepLinkHandler** (`deep_link_handler.dart`): Riverpod provider using `AppLinks()`. In `build()`: await `getInitialAppLink()` for cold start, listen `uriLinkStream` for runtime. Parse `nonce` from `t.me/set3vpn_bot?start=nonce_xxx` or custom scheme. On nonce: start polling `GET /api/mobile/auth/telegram/poll?nonce=...` every 3s (max 60 attempts). On 200 with tokenPair → save to TokenStore → validate via subscription → set authenticated. On 202 continue. On timeout/error → set error.

    10. **App wiring** (`main.dart`, `router.dart`, `theme.dart`, `constants.dart`): `ProviderScope` at root. `go_router` (or custom) with routes: `/auth` (login/register), `/telegram-wait`, `/` (main placeholder). Material 3 theme with Tailwind-inspired colors. Constants: API base URL, storage keys.

    11. **Unit tests**: `token_store_test.dart` (save/read/clear/hasTokens), `auth_notifier_test.dart` (build restores session, login sets authenticated, logout clears), `jwt_utils_test.dart` (isExpired, isExpiringSoon, getExpiry). Use `flutter_test` with mocked `FlutterSecureStorage` and `Dio`.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Mobile App ↔ Backend API | Untrusted network (public internet); JWT in Authorization header |
| Mobile App ↔ Secure Storage | Trusted local boundary; Android Keystore / iOS Secure Enclave |
| Mobile App ↔ Telegram Deep Link | External app (Telegram) launches app with nonce; nonce validated server-side |
| User ↔ Mobile App | Biometric authentication gate on resume |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-18-01 | Spoofing | Deep link handler | high | mitigate | Nonce validated server-side via `/telegram/poll`; nonce TTL 10min; consumed once |
| T-18-02 | Tampering | Token storage | critical | mitigate | `flutter_secure_storage` uses hardware-backed encryption; biometric required on read |
| T-18-03 | Repudiation | Auth state transitions | medium | mitigate | Structured logging (pino) on backend for login/refresh/telegram-bind; client logs via logger |
| T-18-04 | Information Disclosure | JWT in memory | medium | mitigate | Access token 15min TTL; refresh token 30d but rotated on each use; `credentialsChangedAt` watermark revokes old |
| T-18-05 | Denial of Service | Auth interceptor refresh loop | medium | mitigate | `_isRefreshing` gate + request queue; max 1 refresh at a time; exponential backoff on refresh failure |
| T-18-06 | Elevation of Privilege | Biometric bypass | high | mitigate | `enforceBiometrics: false` allows device passcode fallback; `credentialsChangedAt` revokes tokens on password change |
| T-18-SC | Supply Chain | flutter_secure_storage, dio, app_links, riverpod | high | mitigate | All packages verified in RESEARCH.md Package Legitimacy Audit (OK verdict); pinned versions in pubspec.yaml |
