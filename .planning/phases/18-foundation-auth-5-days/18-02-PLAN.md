    Build all remaining mobile auth routes per RESEARCH.md code examples:

    **Register** (`app/api/mobile/auth/register/route.ts`):
    - Zod: `email` (trim, lowercase, email), `password` (min 8, max 256), `confirmPassword` (must match password via `.refine`).
    - Check duplicate: `prisma.user.findUnique({where: {email}})` → 409 `{error: "email_exists"}`.
    - `hashPassword` from `@/lib/password`, `prisma.user.create({data: {email, passwordHash}})`.
    - `issueTokenPair` from `lib/mobile-auth.ts`.
    - Return 200 `{accessToken, refreshToken, expiresIn: 900}`.

    **Refresh** (`app/api/mobile/auth/refresh/route.ts`):
    - Zod: `refreshToken` (min 1).
    - `jwtVerify` with `env.SESSION_SECRET`, HS256.
    - Extract `uid` and `tid` from payload.
    - Check `credentialsChangedAt` watermark: if `payload.iat < floor(credentialsChangedAt/1000)` → 401 `{error: "token_revoked"}`.
    - Rotate: issue new token pair via `issueTokenPair` (which bumps watermark).
    - Return 200 `{accessToken, refreshToken, expiresIn: 900}`.

    **Telegram Nonce** (`app/api/mobile/auth/telegram/nonce/route.ts`):
    - `POST`, no body needed.
    - Generate nonce: `nonce_${randomBytes(16).toString("hex")}`.
    - `prisma.telegramLinkToken.create({data: {token: nonce, expiresAt: new Date(Date.now() + 600000)}})` (10min TTL).
    - Return 200 `{nonce, expiresIn: 600}`.

    **Telegram Poll** (`app/api/mobile/auth/telegram/poll/route.ts`):
    - `GET?nonce=nonce_xxx`.
    - Zod: `nonce` must start with `nonce_`.
    - Query `prisma.telegramLinkToken.findUnique({where: {token: nonce}})`.
    - If not found or expired → 410 `{error: "expired"}`.
    - If consumed → 409 `{error: "already_consumed"}`.
    - If `telegramId === null` → 202 `{status: "pending"}`.
    - If bound: consume token (`consumedAt = new Date()`), `prisma.user.upsert({where: {telegramId: BigInt(telegramId)}, update: {}, create: {telegramId: BigInt(telegramId)}})`, `issueTokenPair`, return 200 `{tokenPair: {accessToken, refreshToken, expiresIn}}`.

    **Telegram Link Helper** (`lib/telegram-link.ts`):
    - `bindTelegramId(nonce: string, telegramId: number): Promise<void>` — find token, check not consumed/expired, set `telegramId`, `consumedAt`. Used by the Telegram bot's `/start nonce_xxx` handler.
    - Export for bot integration (Phase 18 telegram bot handler, or manual for now).

    **Subscription** (`app/api/mobile/subscription/route.ts`):
    - `GET` with `Authorization: Bearer <accessToken>`.
    - `verifyAccessToken` from `lib/mobile-auth.ts` → 401 if null.
    - Return user info: `{user: {id, telegramId}, keys: []}` (stub — Phase 21 fills in ARTEMIDA keys).
    - `export const dynamic = "force-dynamic"`.

    **Prisma Schema** (`prisma/schema.prisma`):

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-18-07 | Spoofing | Login endpoint | high | mitigate | Rate limiting (existing `checkLoginRateLimit`), dummy verify for timing, Argon2id |
| T-18-08 | Tampering | JWT refresh | critical | mitigate | `credentialsChangedAt` watermark revokes old tokens; refresh token rotation on each use |
| T-18-09 | Repudiation | Auth actions | medium | mitigate | Structured logging on every route (userId, route, outcome) |
| T-18-10 | Information Disclosure | Error responses | low | mitigate | Generic error messages; no stack traces or internal details leaked |
| T-18-11 | Denial of Service | Registration spam | medium | mitigate | Rate limiting on register; email verification (future) |
| T-18-12 | Elevation of Privilege | Telegram nonce | high | mitigate | Nonce TTL 10min, single-use consumption, 16-byte random |
| T-18-13 | Tampering | Refresh token reuse | high | mitigate | Rotation: each refresh issues new pair + bumps watermark; old refresh token rejected |
