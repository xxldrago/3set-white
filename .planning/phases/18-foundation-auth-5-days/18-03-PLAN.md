<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| User ↔ Auth Screens | Untrusted input: email, password; validation + sanitization client-side |
| Auth Screens ↔ AuthNotifier | Trusted; Riverpod state management |
| AuthNotifier ↔ Backend API | Untrusted network; Dio with TLS, token auth |
| Telegram App ↔ Flutter App | Deep link with nonce; validated server-side |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-18-14 | Spoofing | Login form | medium | mitigate | Client validation (email format, min 8) + server validation + rate limiting |
| T-18-15 | Tampering | JWT in memory | medium | mitigate | Short TTL (15m); not logged; cleared on logout |
| T-18-16 | Repudiation | User actions | low | accept | Auth actions logged server-side; client logs local |
| T-18-17 | Information Disclosure | Error messages | low | mitigate | Generic user-facing errors; details only in dev logs |
| T-18-18 | Denial of Service | Form spam | low | mitigate | Submit button disabled during loading; debounce |
| T-18-19 | Elevation of Privilege | Deep link hijack | medium | mitigate | Nonce validated server-side; TelegramLinkToken consumed once |
| T-18-20 | Spoofing | Biometric bypass | medium | mitigate | `flutter_secure_storage` enforces biometric on read; fallback to device passcode |
</threat_model>
