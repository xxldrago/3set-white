# SEED-001: Мобильный клиент на базе Karing (Flutter + sing-box/libbox) — два таба, одна кнопка, аккаунты/ключи/оплата

## Why This Matters

Расширяет продукт 3set-white с Telegram-бота и PWA-кабинета на нативное мобильное приложение — главный канал удержания и повторных продаж VPN. Простота (два таба, одна кнопка) снижает порог входа, а серверный пул и биллинг на бэкенде позволяют менять тарифы/протоколы без обновления приложения. Клиент не хранит серверы «в себе» — получает их с бэкенда только при активном ключе.

## Notes

### 1. Общая архитектура (4 слоя)

1. **UI (Flutter)** — экраны, табы, списки серверов, кнопка подключения.
2. **Ядро sing-box (libbox)** — сборка outbound-конфигурации, TUN-интерфейс, проксирование, замер задержек через urltest, статистика трафика.
3. **Нативный VPN-слой** — `VpnService` (Android) и `NetworkExtension` / Packet Tunnel Provider (iOS).
4. **Бэкенд** — аккаунты, пулы серверов, ключи, платежи.

Разделение ответственности жёсткое: клиент — выбор сервера, пинг, подключение, отображение состояния; бэкенд — какие серверы доступны, лимит устройств, действует ли ключ. Менять пул/тарифы/протоколы можно без обновления приложения.

**Из Karing берём:** plumbing TUN (обе платформы), работу с libbox, парсинг подписок/конфигов, логику urltest.
**Не берём:** закрытый `vpn-service`, сложный UI с профилями/правилами/группами (заменяется двумя фиксированными пулами).

### 2. Структура экранов (4 экрана + 1 модальный лист)

- **Экран входа** — email+пароль, «Войти», переключатель «Регистрация», разделитель «или», «Войти через Telegram». Без гостей.
- **Главный экран** — шапка (аватар/почта, чип статуса ключа «до 12.03.2027» / «Ключ истёк» / «Нет ключа», иконка магазина); сегментированный контрол из двух табов («Простой VPN» / «Обход белых списков»); список серверов (карточка «Авто» + серверы с флагом, названием, протоколом, бейджем пинга и нагрузкой); внизу одна большая кнопка подключения; при активном соединении над кнопкой панель (сервер, протокол, IP, таймер, счётчики трафика).
- **Экран покупки ключа** — тарифы, способ оплаты, промокод, кнопка оплаты. Открывается из шапки, баннера «Ключ истёк» и при попытке подключения без ключа.
- **Лист профиля** — почта/Telegram, статус ключа, лимит устройств, kill switch (опц.), «Выйти».

### 3. Авторизация

- **Email+пароль:** регистрация (пароль ≥8 символов, подтверждение, Argon2/bcrypt, письмо-подтверждение) → JWT (access 15 мин, refresh 30 дней); восстановление по коду на почту. Токены в `flutter_secure_storage` (Keychain/Keystore), не в shared_preferences. При старте: refresh → тихое обновление → главный; нет → вход.
- **Telegram (deep-link flow, не Login Widget):** `POST /auth/telegram/start` → одноразовый `nonce` (TTL 5 мин) + `t.me/YourBot?start=nonce` → `url_launcher` → бот шлёт `/start nonce` → бэкенд проверяет nonce, создаёт/привязывает аккаунт → клиент поллит `GET /auth/telegram/status?nonce=...` каждые 2 с → JWT. Если не подтверждён — экран «Подтвердите вход в Telegram» / «Открыть снова».
- Аккаунт один: email+Telegram ведут к одному ключу.

### 4. Два таба = два пула (`mode: simple | whitelist`)

- **«Простой VPN»** — WireGuard, Shadowsocks, VLESS, Hysteria2, Trojan; полный туннель; приоритет скорость/низкий RTT.
- **«Обход белых списков»** — VLESS+Reality с `dest`/`serverName` из белого списка оператора, либо IP/подсети не в блоке, либо CDN-фронтинг; рукопожатие = разрешённый TLS. Опц. профили под оператора (МТС/Билайн/МегаФон/Tele2); Android — по SIM, iOS — вручную.
- Модель сервера: `id, name, country, city, flag, mode, protocol, config (outbound sing-box JSON или share-ссылка), load (0–100), enabled`.
- Конфиги — только при активном ключе; кеш локально (зашифровано) для офлайн-отображения, но подключение проверяет ядро.

### 5. Автопинг и выбор сервера (ключевая логика)

- Пинг = **urltest ядра** (HTTP на `generate_204` через каждый outbound), не ICMP. Для whitelist-таба проверка только через ядро (голый TCP может быть заблокирован, handshake с правильным SNI — проходить).
- Автопинг: после входа/старта, при переключении таба, при смене сети (Wi-Fi↔LTE), по pull-to-refresh. Кеш TTL 60 с, параллелизм 10–16, таймаут 2 с/сервер.
- Алгоритм `connect(mode)`: нет активного ключа → магазин; selected≠auto → ping(selected,1500), fail → тост + auto; auto → свежий кеш 60с? готовый ранкинг : lastGood(≤3 id) pingParallel(800) → alive? target : полный пинг(2000) → target = sortBy(rtt, load).first(); core.start(config), fail → следующий из ранкинга (макс 2 попытки); успех → lastGood[mode].pushFront (dedupe, ≤5).
- **Баг Karing, который надо починить:** urltest не переживает смену сети → слушать `connectivity_plus`, инвалидировать кеш пинга/last-good, переподключаться с ре-пингом.

### 6. Подключение: состояния

- Машина: `idle → pinging → connecting → connected → disconnecting → idle` + `error` из любого. Кнопка: «Подключить» / спиннер «Подключение…» с отменой / «Отключить». Отмена во время connecting прерывает старт ядра и закрывает TUN.
- Android: `VpnService.protect()` от петли маршрутизации; iOS: `NETunnelProvider`. Успех → last-good, таймер, опрос статистики.
- Переключение таба не рвёт туннель; «Подключить» в другом табе = переключение (стоп старого → выбор → старт нового, «Переключение…»). Смена сети → авто-реконнект с ре-пингом. Падение ядра → рестарт ×3 с backoff. Kill switch (опц.): Android always-on, iOS блокировка вне туннеля.

### 7. Покупка ключа и подписка

- Ключ = подписка: токен доступа к конфигам + срок + лимит устройств.
- Тарифы (пример): Старт 30 дн 199 ₽ / Оптимум 90 дн 449 ₽ / Год 365 дн 1290 ₽ — 5 устройств, безлимит.
- Логика: тариф → способ оплаты (карта YooKassa/CloudPayments, СБП QR/deep link) → промокод (`POST /promo/apply`, %) → `POST /payments/create` → `confirmation_url`/SBP-ссылка → виджет/диплинк → webhook бэкенду → активация/продление → поллинг `GET /payments/{id}` каждые 2 с (таймаут 5 мин) → экран успеха → возврат, конфиги разблокированы. Чек на почту.
- Продление: `max(сегодня, текущее окончание) + дни тарифа`. Истёк → баннер, кнопка ведёт в магазин, конфиги не отдаются; опц. grace 1–2 дня. Лимит устройств по `device_id`; при превышении — предложение отключить старое в профиле.

### 8. Хранение и API

- **Secure storage:** access/refresh-токены, токен ключа, кеш конфигов (секреты).
- **Preferences:** выбранный таб, выбранный сервер per-tab, last-good per-tab (id+ts), кеш пинга (id→rtt+ts), кеш статуса подписки, настройки. Истина о подписке — на бэкенде.
- **API:** `POST /auth/register|login|refresh`; `POST /auth/telegram/start`, `GET /auth/telegram/status`; `GET /servers?mode=simple|whitelist`; `GET /subscription`; `POST /payments/create`, `GET /payments/{id}`; `POST /promo/apply`; `POST /devices`, `DELETE /devices/{id}`.

### 9. Ошибки и краевые случаи

| Ситуация | Поведение |
|---|---|
| Нет/истёк ключ | баннер + кнопка в магазин |
| Все серверы таба мертвы | ошибка, «Повторить», подсказка сменить таб |
| Выбранный сервер мёртв | тост + авто→auto |
| Смена сети | инвалидация кеша, ре-пинг, реконнект |
| Падение ядра | рестарт ×3 backoff → ошибка |
| Оплата не подтверждена 5 мин | «Проверить статус» + ручной поллинг |
| Refresh протух | выход на экран входа |
| Telegram не подтверждён | «Открыть снова» / «Войти по email» |
| Серверы не загрузились | кеш + тост офлайн |

### 10. Ограничения

- **Лицензии:** Karing и sing-box — GPL-3.0 → форк обязывает открыть исходники. Для закрытого коммерческого продукта — своя оболочка, ядро как отдельный компонент, юр. проверка; альтернатива Xray-core (MPL-2.0), но тогда Hysteria2/TUIC закрывать иначе.
- **iOS:** entitlement NetworkExtension, review VPN-приложений, privacy labels. **Android:** декларация VpnService, foreground service, политика Play.
- Трафик не логировать, опубликовать политику конфиденциальности. Токен Telegram-бота — только на бэкенде.

### Итоговая формула

**Два пула серверов с бэкенда → автопинг через ядро с быстрым путём по last-good → одна кнопка с честной машиной состояний → ключ как подписка, закрывающая доступ к конфигам.** Всё остальное намеренно вырезано ради простоты.
