# ARTEMIDA API V1 — аудит покрытия

**Дата:** 2026-11-20
**Источник:** `https://artemida.cc/api-docs` (актуальная документация, прочитана вживую) + проверка живьём
**Назначение:** показать, какие возможности API ARTEMIDA реализованы в сервисе, какие нет и что это даёт.

## Сводка

| Всего эндпоинтов в API | Реализовано в сервисе | Не реализовано |
|---|---|---|
| 17 | 12 | 5 |

Все реализованные эндпоинты используются хотя бы в одном канале (сайт или бот).
«Не реализовано» ниже делится на два типа: **нет клиента** (метод не написан) и **есть клиент, нет UI**
(метод написан, но пользователю/оператору не выведен).

---

## 1. Реализовано

| Эндпоинт | Где используется |
|---|---|
| `GET /balance` | Админка (`/admin/wallet`), проверка баланса API |
| `GET /pricing` | Витрина тарифов, расчёт цены, апгрейд |
| `POST /trial` | Trial-ключ (сайт + бот) |
| `POST /keys` | Покупка подписки (сайт + бот) |
| `GET /keys` | Список ключей (кабинет + бот) |
| `GET /keys/{id}` | Актуальное состояние ключа |
| `POST /keys/{id}/renew` | Продление подписки |
| `POST /keys/{id}/upgrade` | Добавление устройств |
| `DELETE /keys/{id}` | Отзыв ключа |
| `GET /keys/{id}/devices` | Список устройств |
| `DELETE /keys/{id}/devices/{token}` | Удаление устройства |
| `POST /keys/{id}/devices/clear` | Сброс всех устройств |

## 2. Не реализовано

### 2.1 Нет клиента, нет UI

| Эндпоинт | Что делает | Зачем нужно | Оценка |
|---|---|---|---|
| `POST /wallet/topups` | Создаёт счёт Platega на пополнение **нашего** API-баланса | Пополнять баланс из админки, не заходя в кабинет ARTEMIDA | ✅ **Реализовано в этой итерации** |
| `GET /wallet/topups/{paymentId}` | Проверяет оплату и зачисляет на баланс (ровно один раз) | Показывать статус пополнения оператору | ✅ **Реализовано в этой итерации** |
| `POST /keys/{id}/traffic` (POST/PATCH) | Меняет лимит трафика ключа; `trafficLimitGb=0` = безлимит | Клиент сам меняет лимит; бесплатно | Клиент добавлен (`setTrafficLimit`), UI нет |
| `POST /keys/{id}/traffic/reset` | Сбрасывает счётчик использованного трафика | «Начать месяц заново» | Клиент есть (`resetTraffic`), UI нет |
| `DELETE /keys/{id}/permanent` | Удаляет ключ навсегда, **без возврата средств** | Чистка мусора | Клиент есть (`deleteKey({permanent:true})`), UI нет |

### 2.2 Есть клиент, нет UI

| Эндпоинт | Что делает | Почему не выведен |
|---|---|---|
| `POST /keys/{id}/disable` | Бесплатно отключает ключ, срок не тратится | Полезно как «пауза», но требует продуктного решения: клиент может случайно оставить себя без VPN |
| `POST /keys/{id}/enable` | Включает ранее отключённый ключ | Пара к `disable` |
| `DELETE /keys/{id}/permanent` | Удаление навсегда без возврата | Опасная операция — только для админа, не для клиента |

### 2.3 Ограничение провайдера (не наша недоработка)

| Возможность | Статус | Детали |
|---|---|---|
| Переименование ключа | ❌ Не поддерживается | `PATCH /keys/{id}` → 501, `PUT /keys/{id}` → 501, `POST /keys/{id}/rename` → 404 `route_not_found`. Проверено живьём 2026-11-20. Реализовано локально (`keys_cache.label`). |
| Переименование устройства | ❌ Не поддерживается | У устройства есть только `name`, которое сообщает VPN-клиент; записать его нельзя. Реализовано локально (`device_labels`). |
| Добавление устройства | ❌ Отдельного метода нет | Устройства регистрируются сами при подключении по subscription-ссылке. «Добавить устройство» в кабинете = увеличить лимит устройств через `POST /keys/{id}/upgrade`. |

## 3. Что стоит реализовать дальше

По убыванию пользы:

1. **Лимит трафика в кабинете** (`PATCH /traffic`). Клиент видит «трафик закончился» и не может ничего
   сделать. Кнопка «поставить лимит» / «сделать безлимит» закрывает реальную боль. Клиент уже готов —
   нужен только роут и UI.
2. **Пауза подписки** (`disable`/`enable`). Полезно для отпуска: срок не тратится, пока ключ выключен.
   Требует решения по UX, чтобы клиент не выключил ключ и не потерял доступ к самому кабинету.
3. **Удаление ключа навсегда** — только в админке. Клиенту не показывать: API не возвращает деньги.
